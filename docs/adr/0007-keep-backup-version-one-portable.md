# Keep backup version 1 portable across platforms

The first Flutter release will both import and export the existing Clock Rhythm backup schema version 1 because its durable product data remains Preferences and Todos. Rhythm Session state, scheduled-notification identifiers, permission state, and device file paths are excluded; Windows automatic-start preference is retained but dormant on Android so round trips do not discard it, while the existing custom-sound sanitization rule remains in force. A new backup version will be introduced only when the serialized product contract actually changes.

A Portable Backup remains plain JSON, and the export flow warns the user that the file is readable without a password. Import validates the complete envelope before showing a replacement summary and asking for explicit confirmation. While applying it, mutating operations are suspended and Preferences and Todos are replaced in one database transaction; any validation or persistence failure leaves existing durable data unchanged. Windows automatic startup is reconciled after that commit because an operating-system side effect cannot share the database transaction; reconciliation failure keeps the imported desired preference and presents a repair action instead of rolling back unrelated user data.

Confirming an import first cancels registered Rhythm Events and active sound, then leaves the local Rhythm Session Idle whether replacement succeeds or fails. The preview explicitly discloses this non-transactional safety effect, and imported data never starts delivery without a later user Start.
