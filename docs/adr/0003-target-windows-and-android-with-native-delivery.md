# Target Windows and Android first with platform-native rhythm delivery

The first Flutter release will support Windows and Android, with iOS deferred until a macOS build, signing, and device-verification environment is available. Both platforms share the rhythm domain, but Windows keeps tray-backed execution, automatic startup, custom MP3 selection, and app-controlled volume, while Android persists an active Rhythm Session and schedules notifications through the operating system; Android requires the relevant notification and timing permissions, exposes their status instead of desktop-only settings, and initially supports only the bundled notification sound or Mute.

Closing the Windows window hides a running process to the tray, explicit quit ends it, and a later ordinary launch starts with an idle Rhythm Session. Windows automatic startup launches hidden to the tray but also starts idle. Android reconstructs and reschedules a running Rhythm Session after device reboot, application update, or wall-clock or time-zone changes. It does not attempt automatic recovery after the user force-stops the application or revokes a required permission; the next foreground launch explains the issue and offers recovery.
