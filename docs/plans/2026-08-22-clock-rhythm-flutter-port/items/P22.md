# [P22] 행동 동등성 감사와 출시 자격 판정

Parent plan:

- [전체 계획](../plan.md)

Status:

- In Progress

Purpose:

- 자동 테스트 수가 아니라 합의된 행동·실기기·설치 artifact 증거를 모두 모아 beta 또는 `1.0.0` 출시 가능 여부를 판정합니다.

Goal linkage:

- 원본 182개 executable 테스트가 보호한 모든 행동과 새 Flutter/Android 규칙에 검증 증거가 있어야 합니다.
- Windows 10/11 x64, Android API 24/31/33/36 emulator와 physical device matrix, 실제 backup round trip과 installed update가 통과해야 합니다.

Required skills:

- [verification-before-completion, systematic-debugging]

Boundary mapping:

- Public interface: completed behavior matrix, platform evidence index, artifact manifest/checksums, release decision record가 release owner에게 공개됩니다.
- Implementation boundary: 이 항목은 feature code를 새로 설계하지 않고 실패를 해당 owning P-item으로 돌려보내 수정·재검증합니다.
- Out-of-scope adjacent behavior: 미검증 항목 waiver로 production claim, coverage percentage 대체, store submission, old app 자동 삭제는 하지 않습니다.
- Regression scenarios: test count만 맞추기, physical evidence 없이 Android 완료, debug build로 release 판정, synthetic backup만으로 legacy 호환 주장, 설치 update data loss를 막습니다.

Files / Resources:

- Create: `docs/verification/{release-evidence-index.md,windows-matrix.md,android-matrix.md,backup-roundtrip.md,installed-update.md}`, `tool/check_release_evidence.ps1`, `artifacts/manifest.json`과 외부 보관 evidence의 checksum/reference.
- Modify: `docs/verification/legacy-behavior-matrix.md`의 모든 행 status/evidence, plan `execution-ledger.md`, release notes/version은 판정 결과에 맞게 갱신합니다.
- Test: 전체 automated suite, release builds, Windows installed/portable flows, Android emulator/physical lifecycle, Neutralino v1 round trip, beta→production import, installed version upgrade, privacy/log inspection.
- Delete: 실패 artifact와 stale evidence reference는 staging에서 제거하되 사용자 설치/data나 old app은 삭제하지 않습니다.

Difficulty:

- 🔴 High

Risk:

- 수동 결과를 실행 환경·artifact hash 없이 기록하면 이후 다른 binary의 성공 증거로 잘못 재사용될 수 있습니다.

Rollback:

- 하나라도 필수 증거가 실패/누락이면 version을 beta로 유지하고 해당 P-item을 Pending/In Progress로 되돌립니다. 배포된 beta는 isolated identity이므로 production/Neutralino data를 건드리지 않고 제거할 수 있습니다.

Completion criteria:

- [x] legacy 49 test files/182 executable test cases의 각 행동 행이 owning P-item과 passing Dart/native/widget/integration/manual evidence 또는 Accepted ADR에 근거한 명시적 대체 처분을 가집니다.
- [ ] 새 규칙인 Gregorian validation, Stop rollover, missed-event skip, permission loss, process recovery, reboot/Doze/time/timezone 변화도 별도 evidence가 있습니다.
- [ ] Windows 10/11 x64에서 window/tray/single-instance/autostart/custom MP3/backup/ZIP/MSIX install/update가 artifact hash별로 통과합니다.
- [ ] Android API 24/31/33/36 emulator와 physical device에서 notification/exact permission, process removal, reboot, Doze, clock/timezone, backup include/exclude, APK/AAB install/update가 통과합니다.
- [ ] 실제 Neutralino v1 export를 Flutter beta에 import/export하고 그 v1을 production에 import해 Preferences/Todos 의미 동등성을 확인합니다.
- [ ] format/analyze/generated/architecture/all tests/native tests/release builds/accessibility/privacy/log/artifact inspection이 모두 green이며 signing 상태가 정확히 표기됩니다.
- [ ] physical-device 또는 installed-update 증거가 없으면 release decision은 beta이고 `1.0.0` production parity로 판정하지 않습니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: evidence checker가 empty/미배정 legacy 행, 누락 artifact hash, 미실행 platform cell을 nonzero로 보고하게 먼저 작성합니다.
   - Expected before implementation: 초기 matrix에 Pending 항목이 있으므로 release qualification은 실패합니다.
2. Minimal implementation:
   - Action: 자동 gate 결과를 기록하고 Windows→Android emulator→physical device→backup roundtrip→installed update 순으로 evidence를 채웁니다. 실패는 owning P-item으로 돌려보냅니다.
3. Passing verification:
   - Command/check: `powershell -ExecutionPolicy Bypass -File tool/verify.ps1`, release packaging/inspection scripts, evidence completeness checker.
   - Expected after implementation: 모든 필수 cell이 artifact hash·환경·날짜·결과와 연결되고 checker가 0을 반환합니다.
4. Regression lock:
   - release evidence index가 artifact manifest와 test report checksum을 묶어 이후 binary가 바뀌면 이전 증거를 자동 무효화합니다.

Notes:

- beta 배포 자체는 P20 기준 artifact가 만들어지고 알려진 blocker가 문서화되면 가능하지만, `1.0.0+1`은 이 항목 전체 통과 후에만 사용합니다.
- 수동 evidence에는 Todo title, 전체 custom path, signing secret 등 개인·비밀 데이터를 기록하지 않습니다.
