# [P3] Preferences 도메인과 Draft 적용 의미 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- 즉시 적용되는 개인화 설정과 Save 전에는 일정에 영향을 주지 않는 Rhythm Settings Draft를 서로 다른 상태로 명확히 모델링합니다.

Goal linkage:

- 기본 설정, 11개 theme ID, 한국어/영어, Mute/volume/custom sound, Windows autostart 호환성을 보존해야 합니다.
- 미저장 draft가 route, tray hide, Android configuration/restorable process death를 견디되 백업이나 활성 일정에는 들어가면 안 됩니다.

Dependencies:

- depends_on: [[P1](P1.md), [P2](P2.md)]
- parallelizable: true

Required skills:

- [code-principles, client-ui-best-practices]

Boundary mapping:

- Public interface: `UserPreferences`, `RhythmSettingsDraft`, `LanguagePreference`, `ThemePreference`, `NotificationSoundPreference`, Preferences query/command와 `SettingsRepository`, `AutoStartPort`, `NotificationSoundFilePort`, `SoundPreviewPort`를 공개합니다.
- Implementation boundary: Preferences Domain이 값과 불변식을 소유하고 Application이 저장·즉시 적용·Save 후 Rhythm 재계산·autostart side effect 순서를 소유합니다. draft 복구 codec은 replaceable device UI state 어댑터 뒤에 둡니다.
- Out-of-scope adjacent behavior: 실제 Drift row, shared_preferences 호출, Windows shortcut, MP3 decode, Android channel은 이후 항목이 맡습니다.
- Regression scenarios: draft가 입력 즉시 일정에 반영됨, mute 시 알림 자체가 사라짐, 0%와 mute 혼동, Android import가 Windows autostart 값을 버림, draft가 Portable Backup에 포함됨을 막습니다.

Files / Resources:

- Create: `lib/contexts/preferences/domain/{user_preferences.dart,rhythm_settings_draft.dart,language_preference.dart,theme_preference.dart,notification_sound_preference.dart}`, `lib/contexts/preferences/application/ports/{settings_repository.dart,auto_start_port.dart,notification_sound_file_port.dart,sound_preview_port.dart,draft_store.dart,preferences_changed_port.dart}`, `lib/contexts/preferences/application/{get_preferences.dart,save_rhythm_settings.dart,change_language.dart,change_theme.dart,change_notification_sound.dart,change_volume.dart,toggle_mute.dart,complete_initial_setup.dart}`, `lib/contexts/preferences/public.dart`, `lib/contexts/preferences/public_model.dart`, 해당 domain/application 테스트.
- Modify: `docs/verification/legacy-behavior-matrix.md` Preferences 행.
- Test: default/restore snapshot, invalid present value, mute round trip, volume bounds, save/side-effect ordering, draft serialize/restore/discard fixture.
- Delete: 없음.

Difficulty:

- 🔴 High

Risk:

- 하나의 mutable settings map으로 durable preference와 draft와 platform capability를 섞으면 저장 실패, import, Android의 축소된 sound 기능에서 상태가 서로 오염됩니다.

Rollback:

- 즉시 적용 command와 draft Save command를 별도 변경 단위로 유지합니다. side effect가 실패하면 durable desired state를 되돌리지 않는 합의가 있으므로, adapter를 비활성화하고 repair 상태를 표시하는 쪽으로 복구합니다.

Completion criteria:

- [ ] 기본값은 Focus 50, Rest 10, Daily Rhythm 05:00–18:00, `kor`, `current`, bundled default sound, volume 1.0, autostart off, initial setup false입니다.
- [ ] Focus/Rest/Daily Rhythm/Windows autostart는 draft에만 바뀌며 성공한 Save가 durable Preferences를 갱신한 뒤 Rhythm rescheduler와 autostart reconciliation을 호출합니다.
- [ ] language/theme/sound/volume은 별도 command로 즉시 durable 적용되고, active Android 일정의 발생 시각을 바꾸지 않은 채 payload 재등록을 요청할 수 있습니다.
- [ ] Windows Mute 해제는 직전 default/custom 선택과 volume을 복구하고 0%는 Mute가 아니며, Android Mute 해제는 bundled default로 돌아갑니다.
- [ ] Android는 Windows `autoStartEnabled` 값을 durable/Portable Backup round trip을 위해 휴면 상태로 보존하지만 control이나 OS side effect를 노출하지 않습니다.
- [ ] draft는 성공한 Save 또는 확인된 import 때 durable 값으로 reset되고 Portable Backup snapshot에는 어떤 draft 필드도 없습니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: `fvm flutter test test/contexts/preferences/domain test/contexts/preferences/application`에서 default snapshot, save ordering, mutedFrom, draft 생존/제외 사례를 먼저 실행합니다.
   - Expected before implementation: 타입 부재 또는 port 호출 순서 불일치로 각 테스트가 의도한 이유로 실패합니다.
2. Minimal implementation:
   - Action: immutable domain 객체와 명시적인 command를 작성하고, 외부 효과는 작은 port로 주입합니다. `saveRhythmSettings`만 rhythm-affecting 값과 autostart draft를 commit합니다.
3. Passing verification:
   - Command/check: `fvm flutter test test/contexts/preferences --reporter expanded`와 architecture check.
   - Expected after implementation: 유효성·기본값·상태 전이·실패 결과가 통과하며 Preferences Application이 구체 plugin이나 UI를 import하지 않습니다.
4. Regression lock:
   - Preferences snapshot contract와 draft 비포함 테스트, fake port 호출 순서 테스트가 import/save/immediate 설정 의미를 잠급니다.

Notes:

- legacy `kor`는 durable/backup 호환 ID로 유지하고 Flutter locale에서만 `ko`로 매핑합니다.
- theme ID 11개는 exact string union/value object로 고정합니다. 사용자 표시명과 palette는 P9가 별도 catalog로 소유합니다.
- Custom Notification Sound의 복사된 private path는 device-specific infrastructure 값이며 Portable Backup serializer에는 절대 노출하지 않습니다.
