# [P15] Windows 알림과 알림음 전달 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- In Progress

Purpose:

- tray에서 살아 있는 Windows 세션이 각 Rhythm Event에 OS 알림과 한 번 재생되는 default/custom sound를 현재 preference로 전달하게 합니다.

Goal linkage:

- custom MP3 ≤20MiB private copy, decoder validation, app volume, Mute, preview, fallback/repair 계약을 보존해야 합니다.
- Mute여도 visible notification을 남기고 다음 event가 active notification을 교체해야 합니다.

Dependencies:

- depends_on: [[P3](P3.md), [P5](P5.md), [P8](P8.md), [P9](P9.md), [P10](P10.md), [P12](P12.md), [P14](P14.md)]
- parallelizable: false

Required skills:

- [code-principles, systematic-debugging]

Boundary mapping:

- Public interface: rhythm-owned `NotificationPort`/`EventSoundPort`, preferences-owned `NotificationSoundFilePort`/`SoundPreviewPort`와 typed failures만 application에 보입니다.
- Implementation boundary: OS notification adapter, audio player lifecycle, MP3 structural/decoder validator, private media store를 각각 작은 infrastructure 객체로 둡니다.
- Out-of-scope adjacent behavior: Android notification channel/alarm, media backup, OS notification history 삭제·보존 정책 제어는 하지 않습니다.
- Regression scenarios: Mute가 알림까지 제거, source path 의존, preview loop, Pause 후 audio 지속, corrupt custom에서 preference silently reset, 다음 event가 이전 sound를 이어 재생함을 막습니다.

Files / Resources:

- Create: `lib/contexts/rhythm/infrastructure/windows/{windows_notification_adapter.dart,windows_event_sound_adapter.dart}`, `lib/contexts/preferences/infrastructure/windows/{windows_notification_sound_file_adapter.dart,mp3_structure_validator.dart,private_sound_store.dart,windows_sound_preview_adapter.dart}`, adapter contract/integration tests와 MP3 fixtures.
- Modify: composition wiring, `pubspec.yaml`의 `flutter_local_notifications`, `audioplayers`, `file_picker`, `path_provider`; P10 sound panel port binding.
- Test: default/custom/muted/0%, selection cancel, >20MiB, wrong extension, invalid frame, decoder failure, source deletion, atomic replacement fault, preview/event lifecycle, stable notification ID/group/tag.
- Delete: 없음.

Difficulty:

- 🔴 High

Risk:

- 기존 custom file을 먼저 덮어쓴 뒤 새 decoder 검증이 실패하면 사용자의 마지막 정상 알림음도 잃습니다.

Rollback:

- versioned private filename에 새 media를 복사·검증하고 durable pointer commit 후 이전 file을 정리합니다. 실패하면 새 임시 파일만 제거하고 기존 pointer/file을 유지합니다. playback adapter 실패 시 bundled sound로 event를 전달하고 repair state를 남깁니다.

Completion criteria:

- [ ] picker는 한 MP3만 받고 extension, 20MiB size, frame structure, 실제 decoder prepare를 모두 통과한 뒤 private versioned path로 채택합니다.
- [ ] 원본 파일을 이동·삭제해도 copied media가 재생되고 Portable Backup에는 binary와 private/source path가 없습니다.
- [ ] preview와 event는 loop 없이 처음부터 한 번 재생하고 completion에서 playing state를 지웁니다. sound mode change/Pause/Stop for Today/Quit은 현재 playback을 중단합니다.
- [ ] 다음 Rhythm Event는 이전 playback을 멈추고 처음부터 시작하며, custom decode/play 실패는 해당 event에 bundled fallback을 재생하고 preference를 유지한 채 repair action을 표시합니다.
- [ ] Mute와 volume 0% 모두 OS 알림은 표시하고, Mute만 sound 호출을 생략합니다. Windows는 delivery 순간 최신 language/sound/volume을 읽습니다.
- [ ] 알림은 package가 허용하는 경우 stable group/tag로 active item을 교체하고 이후 notification-center history는 OS에 맡깁니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: fake player/notifier/file system과 실제 small MP3 fixture로 infrastructure contract tests를 먼저 실행합니다.
   - Expected before implementation: adapter 부재 또는 atomicity/playback state assertion으로 실패합니다.
2. Minimal implementation:
   - Action: private store transaction → validator → preference command → preview adapter → event sound adapter → notification adapter 순으로 작성합니다.
3. Passing verification:
   - Command/check: Windows adapter tests, `fvm flutter build windows --release`, 실제 Windows에서 source file 삭제·tray hide·event delivery 수동/자동 harness.
   - Expected after implementation: visible toast와 sound mode별 실제 출력, fallback, cleanup이 기대와 같고 release log에 전체 path/title이 없습니다.
4. Regression lock:
   - fault-injected file adoption, audio lifecycle fake, Windows artifact smoke가 media ownership·Mute·fallback을 잠급니다.
