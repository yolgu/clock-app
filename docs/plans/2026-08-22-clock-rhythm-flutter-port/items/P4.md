# [P4] Todo 도메인과 애플리케이션 동작 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- Todo를 시각·알림 이벤트가 아닌 Local Calendar Date에 놓인 개인 약속으로 모델링하고 편집·완료·이동·정렬 규칙을 한곳에 둡니다.

Goal linkage:

- 기존 Todo/calendar 기능과 backup snapshot을 보존하면서 Gregorian 날짜 검증과 설치당 25,000개 제한을 추가해야 합니다.
- incomplete/completed Completion Group별 사용자 순서와 deterministic tie-break를 모든 화면·저장소가 공유해야 합니다.

Dependencies:

- depends_on: [[P1](P1.md)]
- parallelizable: true

Required skills:

- [code-principles]

Boundary mapping:

- Public interface: `Todo`, `TodoTitle`, `LocalCalendarDate`, `TodoTime`, `CompletionGroup`, snapshot/command DTO와 Todo query/command use case만 공개합니다.
- Implementation boundary: 값 검증·완료 상태·날짜 이동·그룹 순서는 Domain, repository load/save와 ID/Clock 사용 순서는 Application에 둡니다.
- Out-of-scope adjacent behavior: Drift SQL, widget drag handle, calendar grid painting, reminder 알림은 다루지 않습니다.
- Regression scenarios: timezone 변경으로 Todo 날짜 이동, completed 숨김, 그룹 밖 reorder, 날짜 이동 시 중간 삽입, optional time으로 자동 정렬·알림 생성, 25,001번째 추가를 막습니다.

Difficulty:

- 🟡 Medium

Risk:

- UTF-16 `String.length`이나 UTC `DateTime`으로 값을 판단하면 한글·emoji 제목 길이와 여행/시간대 변경 시 날짜 의미가 깨집니다.

Rollback:

- persistence를 붙이기 전 snapshot fixture와 pure tests를 기준점으로 둡니다. 새 정렬 규칙에서 문제가 생기면 repository를 건드리지 않고 `TodoCollection`의 ordering 정책만 이전 검증 상태로 되돌립니다.

Completion criteria:

- [ ] Todo Title은 trim 후 단일 행, 1–160 user-perceived characters이며 UI가 120자부터 counter를 표시할 수 있는 길이 정보를 제공합니다.
- [ ] Local Calendar Date는 `YYYY-MM-DD` 실제 Gregorian 날짜이고 timezone/UTC 변환을 하지 않으며 Todo Time은 유효한 optional `HH:mm` 표시값일 뿐입니다.
- [ ] 목록은 incomplete group 후 completed group, 각 group에서 `displayOrder`, `createdAt`, `id` 순으로 deterministic하게 정렬됩니다.
- [ ] 완료/재개는 기존 `displayOrder`를 유지하고, reorder는 같은 날짜·같은 Completion Group의 전체 순열만 받으며, 날짜 이동은 대상 group 끝에 append합니다.
- [ ] 삭제는 즉시 영구 처리되고 undo token을 반환하지 않으며, 설치 전체가 25,000개면 create가 명시적 domain failure를 반환합니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: `fvm flutter test test/contexts/todo/domain test/contexts/todo/application`에 invalid leap date, emoji grapheme, cross-group reorder, date move append, 25,001 create를 먼저 추가합니다.
   - Expected before implementation: 대상 타입 부재 또는 명시된 invariant 위반으로 실패합니다.
2. Minimal implementation:
   - Action: value object와 immutable Todo를 만든 뒤 `TodoCollection`이 순서·limit 규칙을 소유하게 하고, use case가 repository·secure random ID generator·Clock을 조율합니다.
3. Passing verification:
   - Command/check: `fvm flutter test test/contexts/todo --reporter expanded`와 architecture check.
   - Expected after implementation: 모든 유효성·전이·정렬 표가 통과하고 Todo Domain은 Flutter/intl/SQLite를 import하지 않습니다.
4. Regression lock:
   - legacy snapshot fixture와 새 Gregorian/limit 테스트를 traceability 표에 연결해 persistence와 UI가 domain order를 재구현하지 못하게 합니다.

Notes:

- ID는 128자 이하의 nonempty string입니다. infrastructure의 `SecureRandomTodoIdGenerator`가 시간값과 secure random bytes로 충돌 저항 ID를 만들며 Domain은 생성 알고리즘을 알지 않습니다.
- `createdAt`과 `updatedAt`은 저장·backup을 위한 instant이고, `updatedAt >= createdAt`을 restore 시 검증합니다. 이 instant가 Local Calendar Date를 대신하지 않습니다.
