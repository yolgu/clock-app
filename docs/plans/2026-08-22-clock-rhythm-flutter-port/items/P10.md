# [P10] Preferences와 Rhythm Settings Draft 화면 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- 사용자가 활성 설정과 미저장 draft를 혼동하지 않고 rhythm, 언어, theme, sound, 플랫폼 상태를 조작할 수 있는 Riverpod presentation을 만듭니다.

Goal linkage:

- rhythm/autostart는 명시적 Save, language/theme/sound는 즉시 적용되어야 합니다.
- Windows는 autostart/custom MP3/volume을, Android는 notification·exact alarm permission 상태와 bundled default/Mute만 보여야 합니다.

Dependencies:

- depends_on: [[P3](P3.md), [P5](P5.md), [P7](P7.md), [P8](P8.md), [P9](P9.md)]
- parallelizable: false

Required skills:

- [client-ui-best-practices, code-principles]

Boundary mapping:

- Public interface: `PreferencesViewModel`/Riverpod Notifier, `RhythmSettingsPanel`, `NotificationSoundPanel`, `ThemePage`, `PermissionStatusPanel`이 presentation 표면입니다.
- Implementation boundary: Notifier는 application command/result를 화면 상태로 번역하고, field focus/error/preview 같은 일시 상태는 가장 가까운 StatefulWidget이 소유합니다. platform capability는 주입된 model로 분기합니다.
- Out-of-scope adjacent behavior: 실제 Windows file copy/audio와 Android permission intent는 port 구현 전 fake로 검증합니다.
- Regression scenarios: input change 즉시 schedule 변경, unsaved 표시 누락, route 이동 시 draft 소실, Android에 autostart/custom/volume 노출, sound mode 변경 후 preview 지속을 막습니다.

Files / Resources:

- Create: `lib/contexts/preferences/presentation/{preferences_view_model.dart,preferences_providers.dart}`, `lib/contexts/preferences/presentation/settings/{rhythm_settings_panel.dart,duration_field.dart,clock_time_field.dart,rhythm_settings_summary.dart}`, `lib/contexts/preferences/presentation/sound/{notification_sound_panel.dart,sound_preview_button.dart}`, `lib/contexts/preferences/presentation/theme/theme_page.dart`, `lib/contexts/preferences/infrastructure/device_state/shared_preferences_draft_store.dart`, widget/Notifier/restoration tests.
- Modify: `/clock` composition에 settings panel, `/theme` branch, app restoration configuration, `pubspec.yaml`의 `shared_preferences` 직접 의존 선언.
- Test: first-save disclosure, dirty/discard/save, invalid bounds/window, immediate commands, platform capability variants, restoration bucket/process round trip, preview stop/error/repair UI.
- Delete: placeholder Theme/Preferences UI.

Difficulty:

- 🔴 High

Risk:

- Riverpod provider state와 `RestorationMixin`/shared_preferences가 각각 draft truth를 가지면 process restore 뒤 active/draft 값이 뒤바뀔 수 있습니다.

Rollback:

- durable Preferences를 건드리지 않고 draft store를 비활성화해 current session memory로 축소할 수 있습니다. Save가 실패하면 draft와 dirty 표시를 그대로 유지하고 활성 설정을 다시 읽습니다.

Completion criteria:

- [ ] panel은 `initialSetupCompleted == false`인 동안 expanded이고 첫 성공 Save 후 사용자가 접을 수 있습니다.
- [ ] Focus 1–180, Rest 1–60, strict `HH:mm`, start≠end, 첫 Focus보다 짧은 창을 inline error로 막고 Save button은 전체 draft가 유효할 때만 실행됩니다.
- [ ] dirty 표시와 Discard가 있고 route/tray/configuration/restorable process death 후 draft가 복원되며 Save/confirmed import가 durable snapshot으로 reset합니다.
- [ ] language/theme/sound/volume은 즉시 적용되고 sound mode 변경은 preview를 중단합니다. Windows 0%는 Mute와 별도 경고를 표시합니다.
- [ ] Android는 9분 미만 Focus/Rest에 deep-idle 지연/skip 경고를 보이고 permission status/settings link를 표시하며 custom MP3·volume·autostart controls를 렌더링하지 않습니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: `fvm flutter test test/contexts/preferences/presentation`에 fake application ports로 dirty/save/discard/restoration/platform variant 흐름을 먼저 작성합니다.
   - Expected before implementation: widget/Notifier 부재 또는 draft owner 중복 때문에 실패합니다.
2. Minimal implementation:
   - Action: Notifier의 immutable state와 command mapping을 먼저 만들고, draft field widgets, restoration adapter, platform capability panels 순으로 붙입니다.
3. Passing verification:
   - Command/check: presentation tests, `fvm flutter test --update-goldens`로 승인된 baseline 생성 후 일반 golden run, analyzer.
   - Expected after implementation: 두 locale·두 platform profile·compact/wide에서 상태 흐름과 error semantics가 통과합니다.
4. Regression lock:
   - Notifier command-order tests, restoration round-trip, platform snapshot goldens가 draft와 즉시 적용 경계를 잠급니다.

Notes:

- custom sound 실패 repair action의 실제 처리는 P15, Android permission action은 P16이 port를 채웁니다.
- time input은 OS picker 설정을 따르지 않고 `HH:mm` text/24-hour picker 계약을 유지합니다.
