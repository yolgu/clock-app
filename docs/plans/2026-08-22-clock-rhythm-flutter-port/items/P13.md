# [P13] Data Transfer와 데이터베이스 복구 화면 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- Portable Backup export/import와 DB startup failure 복구를 사용자가 위험과 결과를 이해한 상태에서 실행할 수 있게 합니다.

Goal linkage:

- import는 parse/preview/confirm/full replacement 흐름이어야 하고 plain JSON·세션 종료·custom sound sanitization을 사전에 알려야 합니다.
- DB corruption/migration 실패 때 retry/import/reset을 제공하되 silent reset을 금지해야 합니다.

Dependencies:

- depends_on: [[P5](P5.md), [P6](P6.md), [P7](P7.md), [P8](P8.md), [P10](P10.md), [P12](P12.md)]
- parallelizable: false

Required skills:

- [client-ui-best-practices, code-principles, systematic-debugging]

Boundary mapping:

- Public interface: `DataTransferViewModel`, `DataPage`, `BackupImportPreviewDialog`, `DatabaseRecoveryPage`, `BackupFilePort` adapter 결과가 presentation 계약입니다.
- Implementation boundary: file picker/read/write는 infrastructure, prepare/confirm 순서는 P6 application, dialog/navigation과 localized feedback은 presentation이 소유합니다.
- Out-of-scope adjacent behavior: merge/conflict resolution, encrypted/password backup, cloud/account/sync, automatic legacy private-store read는 추가하지 않습니다.
- Regression scenarios: file 선택 즉시 overwrite, title preview/log 노출, cancel 뒤 import 실행, failure 때 dialog stale state, recovery reset 무확인 실행을 막습니다.

- Modify: `/data` branch, startup coordinator/router redirect, app composition의 platform file adapter wiring.
- Test: export cancel/success/failure, oversized read, valid/invalid prepare, preview contents/redaction, confirm/cancel, session stop warning, transaction failure, recovery retry/import/reset confirmation.
- Delete: `/data` placeholder.

Difficulty:

- 🔴 High

Risk:

- picker adapter가 전체 파일을 memory에 읽은 뒤 크기를 확인하면 32MiB 제한이 resource exhaustion 보호 역할을 하지 못합니다.

Rollback:

- export와 prepare-import는 durable state를 바꾸지 않으므로 안전하게 adapter/UI만 되돌릴 수 있습니다. confirm path 문제에서는 버튼을 비활성화하고 기존 DB 및 prepared preview를 보존합니다.

Completion criteria:

- [ ] export는 Preferences/Todos v1 JSON만 저장하고 파일이 암호화되지 않은 readable plain text임을 저장 전에 경고합니다.
- [ ] import adapter는 stat/stream limit로 32MiB를 넘는 입력을 full allocation 전에 거부하고 prepare가 성공해야 preview와 confirm이 열립니다.
- [ ] preview는 total/completed/date range/rhythm/language/theme/autostart/export time/custom sanitization과 “확인 즉시 active session/audio가 끝나며 실패해도 Idle”을 표시하고 Todo title은 표시하지 않습니다.
- [ ] cancel은 durable/session 상태를 전혀 바꾸지 않고, confirm 중 mutating UI commands를 suspend하며 성공·실패 후 draft/Preferences/Todo views를 정확히 refresh합니다.
- [ ] DB recovery는 원본 DB 보존 사실을 보여주고 Retry, Portable Backup Import, 명시적 이중 확인 Reset만 제공하며 reset 전에 recovery copy 경로를 만듭니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: `fvm flutter test test/features/data_transfer/presentation test/app/presentation/recovery`에서 fake file/application ports와 fault DB를 사용합니다.
   - Expected before implementation: 화면 부재 또는 side-effect ordering/redaction assertion으로 실패합니다.
2. Minimal implementation:
   - Action: ViewModel state machine `idle → picking → preparing → prepared → confirming → success/failure`와 별도 recovery state machine을 작성한 뒤 widgets와 adapter를 붙입니다.
3. Passing verification:
   - Command/check: presentation tests, real temporary-file adapter tests, P6 integration tests, analyzer.
   - Expected after implementation: cancel/error/retry를 포함한 모든 상태가 terminal 또는 retry 가능한 상태로 정리되고 기존 data invariant가 유지됩니다.
4. Regression lock:
   - preview snapshot, no-title log capture, oversized streaming fixture, recovery reset confirmation tests가 destructive flow를 잠급니다.

Notes:

- Android file access는 Storage Access Framework를 사용하는 `file_picker` 결과만 읽고 broad storage permission을 요청하지 않습니다.
- export default filename에는 product와 UTC export timestamp를 넣되 사용자가 picker에서 변경할 수 있습니다.
