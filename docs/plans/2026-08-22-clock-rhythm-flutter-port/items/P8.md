# [P8] 한국어·영어 localization과 24시간 표기 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- 사용자 문구, 오류, 접근성 label, 날짜 형식을 Flutter `gen_l10n`의 검증 가능한 한국어·영어 catalog로 옮깁니다.

Goal linkage:

- legacy `kor` preference를 Flutter `ko` locale로 호환하면서 한국어/영어 기능 동등성을 유지해야 합니다.
- Daily Rhythm과 Todo Time은 OS 12시간 설정과 무관한 `HH:mm`, 날짜·월·요일은 locale에 맞는 표시를 사용해야 합니다.

Dependencies:

- depends_on: [[P1](P1.md)]
- parallelizable: true

Required skills:

- [client-ui-best-practices, code-principles]

Boundary mapping:

- Public interface: generated `AppLocalizations`, `LanguagePreference`↔`Locale` mapper, local date/time formatter가 presentation에 제공됩니다.
- Implementation boundary: ARB가 사용자 문구의 SSOT이고 domain failure key를 presentation이 localized message로 변환합니다.
- Out-of-scope adjacent behavior: domain validation 메시지에 UI 문구를 넣거나 Android native notification copy를 Kotlin에 중복 작성하지 않습니다.
- Regression scenarios: 한국어 key 누락, 영어 fallback 노출, `kor`를 지원하지 않는 locale로 전달, 12시간 picker 변환, 매초 live-region 낭독을 막습니다.

Files / Resources:

- Create: `lib/l10n/app_ko.arb`, `lib/l10n/app_en.arb`, `lib/shared/i18n/{language_locale_mapper.dart,localized_failure_mapper.dart,local_date_formatter.dart,clock_time_formatter.dart}`, generated localization output, `test/shared/i18n/**`, `test/l10n/catalog_parity_test.dart`.
- Modify: `l10n.yaml`, `lib/app/clock_rhythm_app.dart`, 모든 presentation 항목이 추가될 때 literal user-facing text를 ARB key로 대체합니다.
- Test: ARB key/placeholder parity, `kor`/`en` mapping, 24-hour parsing/format, Korean/English calendar labels, plural/count messages, native notification payload localization fixture.
- Delete: UI와 adapter에 흩어진 한국어·영어 literal.

Difficulty:

- 🟡 Medium

Risk:

- native background delivery용 문구와 Flutter ARB가 따로 진화하면 앱 언어를 바꾼 뒤 Android 알림이 이전 언어 또는 다른 의미를 보일 수 있습니다.

Rollback:

- ARB key 이름은 안정적으로 유지하고 번역 문구만 되돌립니다. native payload는 문자열이 아니라 localized Dart 결과를 예약 시 저장하도록 해 Kotlin catalog 복제를 피합니다.

Completion criteria:

- [ ] `app_ko.arb`와 `app_en.arb`가 같은 key·placeholder·plural 계약을 가지며 generated file consistency check가 통과합니다.
- [ ] durable `kor`는 `Locale('ko')`, `en`은 `Locale('en')`으로 매핑되고 지원하지 않는 OS locale이 preference를 덮어쓰지 않습니다.
- [ ] persisted/editable clock 값은 항상 strict `HH:mm`이고 날짜·month·weekday 설명만 locale formatter를 거칩니다.
- [ ] backup indexed errors, DB recovery, permission, tray-visible copy, accessibility announcements까지 모두 stable failure/event key로 번역됩니다.
- [ ] language 변경 시 현재 UI가 즉시 바뀌고 P16이 같은 발생 시각의 미래 Android payload 재등록을 요청할 수 있습니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: `fvm flutter gen-l10n` 후 `fvm flutter test test/l10n test/shared/i18n`에 key parity와 formatter fixtures를 먼저 둡니다.
   - Expected before implementation: ARB 또는 mapper가 없어 실패합니다.
2. Minimal implementation:
   - Action: 원본 `kor.json`/`en.json`의 활성 문구를 ARB로 옮기고, 새 합의 오류·권한·접근성 문구를 같은 key set에 추가한 뒤 domain failure mapper를 작성합니다.
3. Passing verification:
   - Command/check: `fvm flutter gen-l10n`, localization tests, `fvm flutter analyze`.
   - Expected after implementation: 두 locale에서 placeholder 오류 없이 codegen과 tests가 통과하고 UI source의 user-facing literal 검사도 통과합니다.
4. Regression lock:
   - catalog parity test와 literal scan이 새 기능에서 한 언어만 추가되거나 domain에 번역 문자열이 들어가는 것을 막습니다.

Notes:

- 앱 시작 시 OS locale을 자동 채택하는 대신 durable user preference가 언어의 SSOT입니다.
- digital clock semantics는 포커스를 받을 때 현재 시간을 읽을 수 있으나 매초 live announcement를 보내지 않습니다.
