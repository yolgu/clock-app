# [P21] 설정·마이그레이션·운영·검증 가이드 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- 개발자와 사용자가 도구체인 준비, beta 공존, JSON 이동, production 전환, 롤백, 플랫폼 제약을 실수 없이 수행할 문서를 제공합니다.

Goal linkage:

- migration은 Neutralino private storage를 읽지 않고 v1 Portable Backup으로만 진행해야 합니다.
- production은 old/beta 실행 파일·data·autostart를 삭제하거나 수정하지 않아야 합니다.
- 시스템 provisioning과 Android license는 저장소가 자동 수행하지 않아야 합니다.

Dependencies:

- depends_on: [[P6](P6.md), [P13](P13.md), [P20](P20.md)]
- parallelizable: true

Required skills:

- [domain-modeling]

Boundary mapping:

- Public interface: `README.md`, setup/build/release/migration/verification/privacy/troubleshooting 문서가 사용자·개발자·release owner 계약입니다.
- Implementation boundary: 문서는 실제 scripts/routes/artifact 이름만 참조하며 결정 근거는 ADR, 용어는 `CONTEXT.md`, 실행 상태는 plan ledger를 링크합니다.
- Out-of-scope adjacent behavior: 자동 uninstall, private-store migration tool, remote 생성/push, store submission, iOS 준비를 지시하지 않습니다.
- Regression scenarios: old autostart와 Flutter 동시 알림, custom media가 backup에 있다고 오해, beta→prod direct DB copy, 비밀정보 문서 예시 유출을 막습니다.

Files / Resources:

- Create: `docs/setup/windows-android-toolchain.md`, `docs/migration/neutralino-to-flutter.md`, `docs/release/release-process.md`, `docs/verification/platform-checklist.md`, `docs/privacy-and-data.md`, `docs/troubleshooting.md`.
- Modify: `README.md`, `CONTEXT.md`/ADR에는 새로운 결정이 생긴 경우에만 별도 ADR로 추가하고 기존 결정은 plan 문서에서 중복 변경하지 않습니다. `ASSET_NOTICE.md`, `THIRD_PARTY_NOTICES.md` 링크를 README/release artifact에 연결합니다.
- Test: 명령 copy/paste dry run, broken link scan, clean-machine setup walkthrough, migration rehearsal, secret/path redaction review.
- Delete: 활성 기능처럼 보이는 Google Tasks/browser/macOS 안내가 Flutter README에 생성되면 제거하거나 역사적 비목표로만 명시합니다.

Difficulty:

- 🟡 Medium

Risk:

- migration 안내가 “기존 앱 종료/자동 시작 비활성화”보다 import를 먼저 지시하면 두 rhythm source가 동시에 알림을 보낼 수 있습니다.

Rollback:

- 실제 앱이나 old data를 자동 변경하지 않으므로 잘못된 문서는 수정 배포할 수 있습니다. migration 중 사용자는 old/beta stores와 pre-cutover JSON을 유지해 이전 앱으로 돌아갑니다.

Completion criteria:

- [ ] setup guide가 Flutter/FVM, VS C++ workload, Android Studio/SDK API 36, `flutter doctor`, 사용자 주도 license acceptance를 명령·예상 결과와 함께 설명합니다.
- [ ] beta는 imported autostart preference로 자기 전용 registration을 가질 수 있지만 hidden launch는 Idle입니다. beta 최초 Start의 coexistence 경고는 한 번만 표시해 Neutralino pause/quit을 요청합니다.
- [ ] guide는 Neutralino export v1 → beta import/검증 → beta export v1 → production import/검증 순서를 사용합니다.
- [ ] production cutover 순서는 pre-cutover backups → old quit/autostart disable → production import/verify → custom MP3 재선택 → old manual uninstall입니다.
- [ ] production은 old/beta executable, private store, autostart entry를 건드리지 않으며 rollback에 DB downgrade/reverse migration을 사용하지 않는다고 명시합니다.
- [ ] README가 지원 플랫폼, build/verify/package commands, privacy/no-network, backup 종류 차이, signing/store 범위, known Android timing limits를 실제 파일과 일치하게 설명합니다.
- [ ] 모든 문서 링크와 명령이 clean checkout에서 검증되고 secret/example 값은 무해한 placeholder입니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: 문서 링크 검사와 각 code block의 명령/경로 존재 검사를 먼저 실행하고 migration 순서 checklist를 reviewer가 따라갑니다.
   - Expected before implementation: 문서 부재 또는 끊어진 command/path 때문에 실패합니다.
2. Minimal implementation:
   - Action: setup → developer README → migration/cutover → release → privacy/troubleshooting → platform checklist 순으로 실제 산출물에서 역으로 문서를 작성합니다.
3. Passing verification:
   - Command/check: link/command checker, clean-machine dry run, Neutralino/beta/prod rehearsal 기록 검토.
   - Expected after implementation: 다른 작업자가 구두 설명 없이 환경 준비·build·migration·rollback 단계를 재현합니다.
4. Regression lock:
   - CI의 link/path scan과 P22 release checklist가 문서와 artifact drift를 막습니다.

Notes:

- iOS는 macOS/Xcode/signing/device 환경이 확보될 때 재검토하며 현재 guide의 지원 플랫폼에 넣지 않습니다.
- Android physical evidence가 없으면 production-ready라고 쓰지 않습니다.
