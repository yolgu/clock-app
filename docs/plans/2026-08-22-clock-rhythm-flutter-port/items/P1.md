# [P1] 컨텍스트 경계와 추적성 제어 확립

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- Dart 코드가 합의된 도메인 경계와 inward dependency를 지키도록 초기 디렉터리, 공개 표면, 자동 검사, 원본 테스트 추적표를 먼저 고정합니다.

Goal linkage:

- `app`, `contexts/rhythm`, `contexts/todo`, `contexts/preferences`, `features/data_transfer`, `shared`의 소유권을 보존해야 합니다.
- 원본 49개 테스트 파일의 182개 executable 보호 행동을 빠짐없이 Dart 증거로 연결해야 합니다.
- 플랫폼 패키지와 `Platform.is*`가 Domain/Application/ViewModel로 새지 않아야 합니다.

Dependencies:

- depends_on: [[P0](P0.md)]
- parallelizable: false

Required skills:

- [directory-architecture, code-principles]

Boundary mapping:

- Public interface: 각 모듈 루트의 `public.dart`, 필요한 `public_model.dart`와 `public_presentation.dart`만 다른 모듈이 import할 수 있습니다.
- Implementation boundary: `tool/check_architecture.dart`와 `test/architecture/**`가 import 방향, composition 소유권, shared 순수성, 공개 표면을 검사합니다.
- Out-of-scope adjacent behavior: 아직 도메인 규칙이나 UI를 채우지 않으며 별도 Dart package로 컨텍스트를 쪼개지 않습니다.
- Regression scenarios: deep import, context에서 `app` 참조, Domain의 Flutter/plugin/Drift 참조, Data Transfer의 구체 repository 참조, `shared`의 비즈니스 참조를 막습니다.

Files / Resources:

- Create: `lib/app/composition/`, `lib/app/navigation/`, `lib/app/presentation/`, `lib/app/infrastructure/`, `lib/contexts/rhythm/{domain,application,infrastructure,presentation}/`, `lib/contexts/todo/{domain,application,infrastructure,presentation}/`, `lib/contexts/preferences/{domain,application,infrastructure,presentation}/`, `lib/features/data_transfer/{application,infrastructure,presentation}/`, `lib/shared/{time,i18n,ui}/`, 각 모듈의 공개 barrel, `tool/check_architecture.dart`, `test/architecture/module_boundaries_test.dart`, `test/architecture/public_surfaces_test.dart`, `test/architecture/shared_purity_test.dart`, `docs/verification/legacy-behavior-matrix.md`.
- Modify: `tool/verify.ps1`에 architecture check를 추가하고 `analysis_options.yaml`에 엄격한 analyzer·lint 규칙과 명시적 public return type 검사를 반영합니다.
- Test: `test/architecture/**`; sibling 원본 저장소의 49개 `*.test.ts(x)`와 182개 executable `it/test` 제목을 고정한 추적 표.
- Delete: 생성 과정에서 생긴 기능 없는 범용 `utils`, `services`, `managers` 폴더가 있으면 공개 API를 만들기 전에 제거합니다.

Difficulty:

- 🟡 Medium

Risk:

- 경계 검사를 파일명 문자열에만 의존하면 import alias, 상대 경로, 생성 코드 때문에 거짓 통과가 생길 수 있습니다.

Rollback:

- 검사기가 오탐을 내면 경계를 완화하지 않고 실패 fixture와 parser를 수정합니다. 디렉터리 뼈대는 코드가 없는 상태이므로 P1에서 추가한 경로와 검사 파일만 역패치할 수 있습니다.

Completion criteria:

- [x] 모든 업무 모듈이 최소 공개 표면을 가지며 외부 import는 그 표면만 사용합니다.
- [x] Domain → Application/Infrastructure/Presentation/Flutter/Drift/plugin, Application → Infrastructure/Presentation 의존이 자동으로 거부됩니다.
- [x] `Data Transfer`는 Preferences와 Todo의 공개 snapshot/use-case 계약만 보고, 교차 컨텍스트 DB transaction의 concrete wiring은 `app/composition` 또는 app-owned infrastructure에만 있습니다.
- [x] 원본 source commit SHA, 49개 테스트 파일, 182개 executable 테스트 제목과 각 행동의 예정 P-item이 `legacy-behavior-matrix.md`에 기록됩니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: fixture에서 Todo 내부 파일 deep import, Domain의 `package:flutter`, shared의 preferences import를 각각 넣고 `fvm dart run tool/check_architecture.dart`를 실행합니다.
   - Expected before implementation: 검사 도구가 없거나 금지 의존을 탐지하지 못해 probe가 실패합니다.
2. Minimal implementation:
   - Action: Dart analyzer AST 또는 package URI를 읽는 검사기로 허용 그래프와 공개 진입점을 코드화하고, 원본 테스트 제목을 안정 ID와 담당 P-item으로 기록합니다.
3. Passing verification:
   - Command/check: `fvm dart run tool/check_architecture.dart`와 `fvm flutter test test/architecture`.
   - Expected after implementation: 실제 뼈대는 통과하고 각 금지 fixture는 파일·행·위반 규칙을 포함한 실패를 냅니다.
4. Regression lock:
   - CI가 모든 변경에서 architecture check와 orphan 공개 API 검사를 실행하고, P22가 추적표의 미배정·미검증 행을 0개로 요구합니다.

Notes:

- layer 폴더는 실제 책임이 생기는 모듈에만 파일을 둡니다. 이름을 맞추기 위한 빈 repository/interface는 만들지 않습니다.
- native 코드는 `android/app`과 `windows/runner`에 남기고 Dart에서는 작은 port를 통해서만 접근합니다.
