# [P20] beta·production identity와 배포 artifact 패키징

Parent plan:

- [전체 계획](../plan.md)

Status:

- In Progress

Purpose:

- Neutralino, Flutter beta, Flutter production을 동시에 설치하고 롤백할 수 있는 독립 identity로 Windows ZIP/MSIX와 Android APK/AAB를 재현 가능하게 만듭니다.

Goal linkage:

- beta는 `0.1.0+1`, production parity는 `1.0.0+1`에서 시작해야 합니다.
- beta artifact는 portable Windows ZIP과 signed Android APK, production은 추가로 MSIX와 AAB를 제공해야 합니다.

Dependencies:

- depends_on: [[P9](P9.md), [P14](P14.md), [P15](P15.md), [P16](P16.md), [P17](P17.md), [P19](P19.md)]
- parallelizable: false

Required skills:

- [code-principles, systematic-debugging]

Boundary mapping:

- Public interface: flavor configuration, artifact manifest/checksums, build scripts와 external signing environment variable 계약이 release owner에게 공개됩니다.
- Implementation boundary: Android Gradle flavors/signing, Windows compile identity/MSIX config, ZIP assembly와 artifact verification script가 packaging 경계입니다.
- Out-of-scope adjacent behavior: Microsoft Store/Google Play enrollment·submission, in-app updater, key 생성·보관, Windows ARM64, iOS/macOS/web/Linux release는 하지 않습니다.
- Regression scenarios: beta/prod storage·autostart 충돌, APK production ID 오염, ZIP DLL/data 누락, secret commit, unsigned artifact를 signed로 표기, update 시 DB 삭제를 막습니다.

Files / Resources:

- Create: `lib/app/config/app_flavor.dart`, Android `src/beta`/`src/production` manifest/resources, external `key.properties.example`, Windows flavor configuration, `msix_config` 또는 flavor별 packaging config, `tool/{package_windows.ps1,package_android.ps1,verify_artifact.ps1}`, `artifacts/manifest.example.json`.
- Modify: `android/app/build.gradle.kts`, `pubspec.yaml` version/tooling, `windows/runner/Runner.rc`, app identity injection, P14 mutex/autostart names, notification channel/tag names.
- Test: install beta+prod side by side, storage/autostart/mutex separation, ZIP clean-machine launch, APK signature/ID/SDK/ABI inspection, MSIX/AAB credential failure, installed upgrade DB retention.
- Delete: committed keystore, certificate, password, generated release artifacts가 source tree에 있으면 제거하고 ignore합니다.

Difficulty:

- 🔴 High

Risk:

- display name만 바꾸고 native package identity, storage key, mutex, autostart registration, notification channel을 공유하면 beta가 production 상태를 변경합니다.

Rollback:

- beta/prod flavor는 별도 application/package identity라 실패 artifact를 uninstall해도 다른 설치 data를 보존합니다. packaging 실패는 source binary를 지우지 않고 staging directory만 폐기합니다. DB downgrade/reverse migration은 시도하지 않습니다.

Completion criteria:

- [ ] production Android ID는 `dev.wndls.clockrhythm`, beta는 `dev.wndls.clockrhythm.beta`이고 두 앱이 동시에 설치되어 별도 DB/no-backup state/notification channel을 가집니다.
- [x] Windows beta/production은 별도 package identity, app data, mutex, toast identity, autostart registration을 사용하고 executable 이름은 `clock_rhythm.exe`입니다.
- [x] beta version `0.1.0+1`은 portable Windows ZIP과 development/beta-signed APK를 만들고, production `1.0.0+1`은 ZIP/APK 외 MSIX/AAB task를 제공합니다.
- [ ] ZIP에는 `clock_rhythm.exe`, Flutter/data/runtime DLL과 필요한 assets가 모두 있고 새 Windows 사용자 환경에서 원본 source/runtime 없이 실행됩니다.
- [x] Android min API 24, compile/target API 36, release Arm32/Arm64와 dev/emulator x64 계약을 artifact inspection으로 확인합니다.
- [x] production signing은 외부 경로/환경 값만 읽고 누락 시 명확히 실패하며 secret과 artifact는 Git에 들어가지 않습니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: flavor별 build 후 `verify_artifact.ps1`이 package ID/version/files/signature를 검사하도록 먼저 작성합니다.
   - Expected before implementation: flavor identity 또는 artifact assembly 부재로 실패합니다.
2. Minimal implementation:
   - Action: runtime flavor model → Android productFlavors → Windows identity resources → staging/ZIP → MSIX/AAB signing boundary → manifest/checksum 순으로 패키징을 작성합니다.
3. Passing verification:
   - Command/check: beta ZIP/APK build+inspection, supplied test certificate가 있는 환경의 MSIX, production signing material이 있는 격리 환경의 AAB; side-by-side install harness.
   - Expected after implementation: artifact metadata·contents·signature와 설치 격리가 manifest 기대값과 일치합니다.
4. Regression lock:
   - identity matrix와 clean-install/update/side-by-side integration이 flavor 충돌과 누락 artifact를 막습니다.

Notes:

- beta APK는 production secret 없이 development/beta signing으로 검증할 수 있습니다. “production signed” 표시는 production owner credential로 생성한 artifact에만 씁니다.
- user-visible semantic build name은 beta `0.1.0`, 첫 parity production `1.0.0`에서 시작하고 platform package용 build number는 `+1`부터 release마다 독립적으로 단조 증가합니다.
- 앱은 self-updater를 포함하지 않습니다. manual/store update가 기존 DB를 열어 P5 migration을 적용합니다.
