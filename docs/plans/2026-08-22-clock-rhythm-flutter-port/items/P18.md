# [P18] 적응형 레이아웃·키보드·복원·접근성 강화

Parent plan:

- [전체 계획](../plan.md)

Status:

- In Progress

Purpose:

- 모든 기능 화면을 Windows·Android의 크기, 방향, text scale, 키보드, TalkBack/Narrator 조건에서 독립적으로 사용할 수 있게 다듬습니다.

Goal linkage:

- Android touch target 48dp, 200% text, portrait/landscape/split-screen/phone/tablet를 지원해야 합니다.
- visible focus, non-color cues, 의미 있는 one-time announcement, standard keyboard와 `Ctrl+1`–`Ctrl+4`를 제공해야 합니다.

Dependencies:

- depends_on: [[P7](P7.md), [P8](P8.md), [P9](P9.md), [P10](P10.md), [P11](P11.md), [P12](P12.md), [P13](P13.md), [P14](P14.md), [P15](P15.md), [P16](P16.md), [P17](P17.md)]
- parallelizable: false

Required skills:

- [client-ui-best-practices, systematic-debugging]

Boundary mapping:

- Public interface: shared focus/semantics/layout primitives와 app-level shortcut map만 각 presentation이 사용합니다.
- Implementation boundary: 각 feature widget이 의미와 reading order를 소유하고 `shared/ui`는 domain-neutral target/focus/layout primitive만 제공합니다.
- Out-of-scope adjacent behavior: 별도 접근성 mode, orientation lock, device-type 하드코딩, 전역 Start/Pause/Delete 단축키는 추가하지 않습니다.
- Regression scenarios: 200% overflow, landscape clipped action, color-only completed/status, calendar arrow focus loss, 매초 time announcement, hidden branch focus 진입을 막습니다.

Files / Resources:

- Create: `lib/shared/ui/{adaptive_content_layout.dart,minimum_tap_target.dart,focus_ring.dart,semantic_status_announcement.dart}`, `lib/app/presentation/app_shortcuts.dart`, `test/accessibility/{semantics_test.dart,target_size_test.dart,text_scale_test.dart,focus_order_test.dart,contrast_test.dart}`, `test/goldens/**`.
- Modify: 모든 page/panel/control, app shell focus traversal, calendar/segmented control key handling, theme derived roles, restoration IDs.
- Test: widths 360/600/720/920/1280, portrait/landscape, text scales 1.0/2.0, ko/en, all 11 theme token contrasts, keyboard matrix, TalkBack/Narrator manual scripts.
- Delete: raw GestureDetector-only actions, unlabeled icon buttons, hard-coded device/orientation branches, global destructive/rhythm accelerators.

Difficulty:

- 🔴 High

Risk:

- final polish로만 접근하면 feature별 semantic ownership과 layout state가 이미 굳어 대규모 재작업이 필요할 수 있습니다.

Rollback:

- feature behavior는 그대로 두고 problematic shared primitive만 feature-local widget으로 되돌릴 수 있습니다. golden 변경은 의도와 ADR 근거 없이 일괄 승인하지 않습니다.

Completion criteria:

- [ ] constraints가 compact 한 열과 실제 공간이 유용한 wide 두 열을 선택하며 route/scroll/form state는 resize·orientation 변경에서 유지됩니다.
- [ ] Android interactive target은 최소 48 logical pixels이고 200% text에서 clipping, inaccessible horizontal scroll, 가려진 primary action이 없습니다.
- [ ] 모든 icon/action/status/calendar cell에 localized role·label·state가 있고 selected/completed/running/error가 color 외 text/icon/shape로도 구분됩니다.
- [ ] Tab/Shift+Tab, Enter/Space, Escape, segmented/calendar arrows와 Windows `Ctrl+1`–`Ctrl+4`가 동작하며 hidden branch에는 focus가 가지 않습니다.
- [ ] 의미 있는 Start/Pause/Resume/Stop/import/error 변화만 한 번 announce하고 1Hz clock은 live region이 아닙니다.
- [ ] all-theme token contrast와 representative layout golden, Flutter accessibility guideline tests, TalkBack/Narrator 수동 점검이 통과합니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: `fvm flutter test test/accessibility test/goldens`에 현재 화면을 200%/small width/keyboard/semantics 조건으로 실행합니다.
   - Expected before implementation: target, overflow, focus, label, contrast 중 구체 항목이 실패합니다.
2. Minimal implementation:
   - Action: page별로 reading order → target/label → keyboard/focus → text scale/layout → color/contrast → restoration 순서로 보강하고 각 실패를 해당 feature test에 고정합니다.
3. Passing verification:
   - Command/check: 전체 widget/golden/accessibility tests와 Windows Narrator·Android TalkBack 체크리스트.
   - Expected after implementation: 자동 검사는 모두 통과하고 수동 스크린리더에서 모든 주요 flow가 pointer 없이 완료됩니다.
4. Regression lock:
   - size/locale/theme matrix golden과 semantic/focus behavior tests가 이후 UI 변경의 접근성 회귀를 막습니다.

Notes:

- all 11 themes는 token/contrast 자동 검사를 받고 golden은 representative high-risk themes만 유지해 baseline 폭증을 피합니다.
- analog clock의 시각 디자인은 유지하되 semantics에는 digital value 하나만 제공합니다.
