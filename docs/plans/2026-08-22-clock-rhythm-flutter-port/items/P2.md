# [P2] Rhythm 도메인과 일정 계산 코어 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- 사용자 상호작용이나 플랫폼 타이머가 아니라 Daily Rhythm 시작점에 고정된 Focus/Rest 경계를 순수 Dart 도메인의 단일 진실로 만듭니다.

Goal linkage:

- 기본 50분 Focus, 10분 Rest, 05:00–18:00 규칙과 교차 자정 창을 정확히 계산해야 합니다.
- Start, Pause, Resume, Stop for Today, 누락 이벤트, 설정 변경의 모든 합의 동작을 Windows와 Android가 공유해야 합니다.

Dependencies:

- depends_on: [[P1](P1.md)]
- parallelizable: true

Required skills:

- [code-principles, systematic-debugging]

Boundary mapping:

- Public interface: `RhythmConfiguration`, `DailyRhythm`, `DailyRhythmWindow`, `ClockTime`, `DurationMinutes`, `RhythmEvent`, `RhythmSchedule`, `RhythmSession`, 그리고 Start/Pause/Resume/Stop/Reschedule use case snapshot만 `public_model.dart`·`public.dart`로 공개합니다.
- Implementation boundary: 날짜·시간 계산과 세션 전이는 Domain, 포트 호출 순서와 다음 발생 예약은 Application에 둡니다.
- Out-of-scope adjacent behavior: OS 알림, 음원 재생, tray, exact alarm, 권한 UI, Drift는 이 항목에서 참조하지 않습니다.
- Regression scenarios: Start 시점부터 새 countdown 시작, Pause 시간만큼 경계 이동, 수면 중 이벤트 catch-up, 교차 자정 Stop 키 오류, end 밖 이벤트 등록을 막습니다.

Files / Resources:

- Create: `lib/contexts/rhythm/domain/{clock_time.dart,duration_minutes.dart,daily_rhythm.dart,rhythm_configuration.dart,rhythm_event.dart,rhythm_schedule.dart,rhythm_session.dart}`, `lib/contexts/rhythm/application/ports/{clock.dart,rhythm_delivery_port.dart,rhythm_status_sink.dart}`, `lib/contexts/rhythm/application/{start_rhythm.dart,pause_rhythm.dart,resume_rhythm.dart,stop_rhythm_for_today.dart,reconcile_rhythm.dart,reschedule_running_rhythm.dart,rhythm_status_snapshot.dart}`, `lib/contexts/rhythm/public.dart`, `lib/contexts/rhythm/public_model.dart`, 대응하는 `test/contexts/rhythm/domain/**`와 `test/contexts/rhythm/application/**`.
- Modify: `docs/verification/legacy-behavior-matrix.md`의 Rhythm 원본 행에 Dart 테스트 경로를 붙입니다.
- Test: fake `Clock`, fake `RhythmDeliveryPort`, local-time/DST/time-zone fixture, 1분·최대값·교차 자정·짧은 창 경계표.
- Delete: 없음.

Difficulty:

- 🔴 High

Risk:

- `DateTime`의 local/UTC 혼용이나 달력 날짜로 Stop 상태를 키잉하면 DST, 자정, 시간대 변경에서 중복·누락 이벤트가 발생합니다.

Rollback:

- 플랫폼 port 호출을 붙이기 전 순수 도메인 commit 단위로 유지합니다. 실패 시 application orchestration만 되돌리고 검증된 value object와 source parity fixture는 보존합니다.

Completion criteria:

- [x] Focus는 정수 1–180분, Rest는 정수 1–60분이며 start=end와 첫 Focus가 창보다 긴 설정은 도메인 오류입니다.
- [x] Schedule은 Daily Rhythm 시작을 anchor로 교대 경계를 계산하고, 창 밖 Start는 다음 창을 arm하며, 누락 경계는 재생하지 않고 현재 시각 뒤 첫 경계만 선택합니다.
- [x] Pause는 무기한이며 원래 경계를 이동시키지 않고 Resume은 다음 미래 경계를 다시 잡습니다.
- [x] Stop for Today는 교차 자정이어도 하나의 창 시작일을 기준으로 남은 경계를 억제하고 다음 Daily Rhythm 시작에서 자동 해제됩니다.
- [x] 실행 중 설정 Save는 이전 예약을 취소하고 새 anchor에서 미래만 다시 계산하며 Paused와 Stopped for Today 의미를 보존합니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: `fvm flutter test test/contexts/rhythm/domain test/contexts/rhythm/application`에 각 결정표를 먼저 추가합니다.
   - Expected before implementation: 아직 없는 타입 또는 잘못된 anchor/상태 전이 때문에 테스트가 의도한 이유로 실패합니다.
2. Minimal implementation:
   - Action: 검증 value object → 창 anchor 계산 → event sequence → session 전이 → port orchestration 순으로 가장 작은 공개 API를 작성합니다. Application은 `Clock`을 주입받고 `DateTime.now()`를 직접 호출하지 않습니다.
3. Passing verification:
   - Command/check: `fvm flutter test test/contexts/rhythm --reporter expanded`와 `fvm dart run tool/check_architecture.dart`.
   - Expected after implementation: 기본/최솟값/최댓값/교차 자정/DST/시간 이동/누락 이벤트/모든 상태 전이 표가 통과하고 Domain에 Flutter·platform import가 없습니다.
4. Regression lock:
   - 원본 Rhythm 테스트와 새 합의 규칙을 `legacy-behavior-matrix.md`에 영구 연결하고, fake clock 기반 테스트가 실제 대기 없이 모든 경계를 검증합니다.

Notes:

- 세션의 사용자 상태는 `idle`, `running`, `paused`, `stoppedForToday`로 표현합니다. 창 밖에서 다음 창을 기다리는 상태는 별도 countdown을 만들지 않고 `running` snapshot의 다음 발생 시각으로 드러냅니다.
- 발생 시각이 정확히 Daily Rhythm 종료와 일치하는 원본 동작은 legacy fixture로 잠그고, 종료를 넘는 경계는 만들지 않습니다.
- Android의 9분 미만 deep-idle 경고는 이 도메인의 유효성 오류가 아니라 P10/P16의 플랫폼 경고입니다.
- DST 경계는 [ADR 0023](../../../adr/0023-resolve-rhythm-boundaries-as-local-civil-time.md)에 따라 누적 local civil minute로 재구성하며, gap의 존재하지 않는 경계는 missed event로 건너뜁니다.
