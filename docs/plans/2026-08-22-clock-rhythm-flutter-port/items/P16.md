# [P16] Android exact alarm·권한·알림 전달 bridge 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- In Progress

Purpose:

- Flutter UI process가 없어도 Android가 한 Rhythm Event씩 정확한 wall-clock 시각에 전달하고, 다음 시각 계산은 계속 공유 Dart 도메인이 소유하게 합니다.

Goal linkage:

- notification permission과 user-granted `SCHEDULE_EXACT_ALARM` 없이는 Start가 Idle을 유지해야 합니다.
- foreground service/permanent notification 없이 AlarmManager와 OS notification을 사용하고 API 24–36을 지원해야 합니다.

Dependencies:

- depends_on: [[P2](P2.md), [P3](P3.md), [P5](P5.md), [P8](P8.md), [P9](P9.md), [P12](P12.md)]
- parallelizable: false

Required skills:

- [code-principles, systematic-debugging]

Boundary mapping:

- Public interface: Dart `AndroidRhythmDeliveryPort`, `AndroidDeliveryCapabilityPort`, typed method-channel DTO와 native `schedule/cancel/status/openSettings/reconcile` calls만 context에 보입니다.
- Implementation boundary: Dart Domain이 event occurrence를 계산하고 Kotlin adapter가 AlarmManager 등록·critical state·BroadcastReceiver·NotificationManager만 소유합니다.
- Out-of-scope adjacent behavior: Kotlin에서 Focus/Rest 산술 재작성, foreground service, full-screen intent, battery optimization exemption, inline notification actions는 금지합니다.
- Regression scenarios: permission 거부 뒤 running 표시, `USE_EXACT_ALARM` 선언, process death 후 next event 소실, 한 event 중복 notification, notification tap이 새 task stack 생성, 언어/Mute 변경 시 시각 shift를 막습니다.

Files / Resources:

- Create: `lib/contexts/rhythm/infrastructure/android/{android_rhythm_delivery_adapter.dart,android_delivery_capability_adapter.dart,android_delivery_dto.dart,android_background_entrypoint.dart}`, `android/app/src/main/kotlin/dev/wndls/clockrhythm/rhythm/{RhythmAlarmBridge.kt,RhythmAlarmReceiver.kt,RhythmNotificationPublisher.kt,RhythmDeliveryStateStore.kt,BackgroundFlutterCoordinator.kt}`, Android unit/Robolectric/instrumentation tests와 Dart contract tests.
- Modify: `android/app/src/main/AndroidManifest.xml`, `android/app/build.gradle.kts`, `MainActivity.kt`, composition wiring, `pubspec.yaml`의 `flutter_local_notifications` 사용 경계.
- Test: API 24/31/33/36 capability table, grant/deny, alarm register/cancel/replace, late delivery skip, background Dart refill, one active notification, tap route, payload re-registration.
- Delete: manifest 또는 plugin이 추가한 `USE_EXACT_ALARM`, foreground-service, full-screen, broad battery/storage 권한이 있으면 제거합니다.

Difficulty:

- 🔴 High

Risk:

- BroadcastReceiver가 현재 event를 전달한 뒤 다음 occurrence를 얻기 전에 Flutter engine 시작이 실패하면 일정이 끊길 수 있습니다.

Rollback:

- native state는 revisioned 파일로 저장하고 새 plan 채택 전 이전 등록을 취소하지 않습니다. bridge 실패 시 Start를 성공 처리하지 않고 Idle로 되돌립니다. 전달 중 refill 실패는 `needsRecovery` marker와 기존 precomputed queue를 보존하고 다음 foreground/P17 lifecycle signal에서 복구합니다.

Completion criteria:

- [ ] manifest는 API 31+용 `SCHEDULE_EXACT_ALARM`과 API 33+ notification permission만 요구하며 `USE_EXACT_ALARM`, foreground service, full-screen intent, battery exemption 요청이 없습니다.
- [ ] 앱 시작이나 Clock/Todo 탐색에서는 permission dialog를 띄우지 않습니다. API 33+ notification permission 요청은 권한이 없는 사용자의 첫 명시적 Start에서만 시작하며, 거부되어도 Rhythm Start 외 기능은 계속 사용할 수 있습니다.
- [ ] Start는 notification permission과 `canScheduleExactAlarms()`를 확인하고 하나라도 없으면 어떤 active state/alarm도 commit하지 않은 채 localized rationale와 settings action을 반환합니다.
- [ ] Dart가 첫 event와 최소 다음 두 future occurrences를 계산해 revisioned delivery plan으로 넘기고 Kotlin은 earliest alarm 하나를 exact API로 등록합니다.
- [ ] receiver는 persisted current payload로 한 OS notification을 게시하고 queue의 다음 alarm을 먼저 등록한 뒤 headless Flutter entrypoint에 현재 local time/config/revision을 전달해 P2가 missed event를 건너뛴 새 queue를 보충합니다. Kotlin은 Focus/Rest 경계를 계산하지 않습니다.
- [ ] critical session/queue/request code/revision/failure marker는 `noBackupFilesDir`에 temp-write, flush, atomic rename으로 저장되고 `shared_preferences`를 사용하지 않습니다.
- [ ] 알림은 bundled default 또는 Mute만 지원하고 Mute여도 visible합니다. stable notification ID로 이전 active item을 교체하며 tap은 기존 task를 재사용해 `/clock`을 선택하고 inline Pause/Stop action은 없습니다.
- [ ] language/Mute 변경은 occurrence timestamp를 그대로 둔 새 revision/payload로 future registrations를 교체합니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: Dart port contract tests와 Gradle `testDebugUnitTest`/Robolectric에서 permission table, atomic state fault, current→next→refill 순서를 먼저 작성합니다.
   - Expected before implementation: bridge 부재 또는 다음 alarm/permission atomicity assertion으로 실패합니다.
2. Minimal implementation:
   - Action: typed channel codec → atomic state store → capability checks → one-alarm scheduler → receiver/publisher → headless Dart refill 순으로 작성합니다.
3. Passing verification:
   - Command/check: `fvm flutter test test/contexts/rhythm/infrastructure/android`, `Push-Location android; .\gradlew.bat testDebugUnitTest; Pop-Location`, API 24/31/33/36 instrumentation smoke.
   - Expected after implementation: process가 종료된 상태에서도 event와 다음 alarm이 이어지고 중복·권한 오표시가 없습니다.
4. Regression lock:
   - shared Dart/native contract suite, revision race tests, manifest permission scan, multi-API instrumentation이 delivery bridge를 잠급니다.

Notes:

- Focus/Rest가 9분 미만이어도 domain 값은 그대로 받습니다. deep idle에서 Android가 delay/skip할 수 있음을 UI가 경고하고 receiver/Dart reconcile은 늦은 경계를 replay하지 않습니다.
- DND, notification channel sound 변경, battery policy를 존중하며 앱은 시스템 설정을 강제로 되돌리지 않습니다.
