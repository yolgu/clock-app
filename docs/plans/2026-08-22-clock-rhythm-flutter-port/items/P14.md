# [P14] Windows 창·단일 인스턴스·트레이·자동 시작 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- In Progress

Purpose:

- Windows에서 창을 닫아도 tray로 계속 동작하고, beta/production별 한 인스턴스와 `--hidden` 자동 시작 계약을 네이티브 runner 경계에서 보장합니다.

Goal linkage:

- 첫 920×680, 최소 720×560, bounds/maximized 복원, monitor clamp를 제공해야 합니다.
- 두 번째 interactive launch는 기존 창을 foreground하고, hidden launch는 기존 창을 띄우지 않아야 합니다.
- ordinary/automatic restart는 항상 Rhythm Session Idle이어야 합니다.

Dependencies:

- depends_on: [[P3](P3.md), [P5](P5.md), [P7](P7.md), [P12](P12.md)]
- parallelizable: false

Required skills:

- [code-principles, systematic-debugging]

Boundary mapping:

- Public interface: app-owned `WindowPort`, rhythm-owned `TrayPort`, preferences-owned `AutoStartPort`, native single-instance channel만 Dart에 보입니다.
- Implementation boundary: window/tray plugin adapters는 Dart infrastructure, single-instance·packaged/unpackaged autostart는 `windows/runner` C++ adapter, capability 선택은 composition root가 소유합니다.
- Out-of-scope adjacent behavior: Rhythm notification/audio는 P15, MSIX identity/signing은 P20이 맡습니다.
- Regression scenarios: close가 process 종료, hidden autostart가 창 표시, 두 인스턴스 알림 중복, offscreen bounds 복원, beta가 production autostart를 덮어씀을 막습니다.

Files / Resources:

- Create: `lib/app/infrastructure/windows/windows_window_adapter.dart`, `lib/contexts/rhythm/infrastructure/windows/windows_tray_adapter.dart`, `lib/contexts/preferences/infrastructure/windows/windows_auto_start_adapter.dart`, `lib/app/application/ports/window_port.dart`, native method-channel wrapper, `windows/runner/{instance_coordinator.h,instance_coordinator.cpp,auto_start_bridge.h,auto_start_bridge.cpp}`, Dart contract tests와 Windows integration harness.
- Modify: `windows/runner/{main.cpp,flutter_window.cpp,flutter_window.h,win32_window.cpp,Runner.rc}`, `lib/app/composition/app_composition.dart`, `pubspec.yaml`의 `window_manager`/`tray_manager`, noncritical window-state store.
- Test: launch matrix interactive/hidden/second instance, close/hide/show/quit, tray actions, bounds clamp, HKCU unpackaged autostart와 MSIX StartupTask status contract.
- Delete: Flutter runner의 기본 close-to-exit 동작과 범용 plugin autostart 구현.

Difficulty:

- 🔴 High

Risk:

- single-instance 확인과 Flutter engine 시작 순서가 경쟁하면 두 프로세스가 모두 tray/notification adapter를 활성화할 수 있습니다.

Rollback:

- native coordinator가 불안정하면 release gate에서 single-instance capability를 실패로 처리하고 artifact를 배포하지 않습니다. 기존 autostart 항목을 무조건 삭제하지 않으며 adapter가 만든 exact beta/prod registration name만 명시적 disable에서 제거합니다.

Completion criteria:

- [ ] runner가 Flutter engine/plugin 초기화 전에 flavor별 per-user mutex를 획득하고, 두 번째 interactive launch는 기존 top-level window에 registered activation message를 보내 show/restore/focus한 뒤 종료합니다.
- [ ] 두 번째 `--hidden` launch는 기존 창에 activation message를 보내지 않고 바로 종료합니다.
- [ ] close button은 창을 hide하고 process/tray/rhythm을 유지하며 tray Quit만 audio/schedule을 취소하고 process를 종료합니다.
- [ ] tray menu는 Open, Pause, Resume, Stop for Today, Quit을 현재 상태·언어에 맞게 활성화하고 각 click이 정확한 application command 하나를 호출합니다.
- [ ] 첫 window는 920×680, min 720×560이며 device-local bounds/maximized를 복원하되 현재 monitor work area 안으로 clamp합니다. 이 상태는 Portable Backup에 없습니다.
- [ ] unpackaged ZIP은 quoted executable + `--hidden`의 exact HKCU registration, MSIX는 package StartupTask API를 사용하며 desired/actual/needs-user-action/error를 명시적으로 반환합니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: Dart port contract tests와 PowerShell launch harness로 1차 interactive, 2차 interactive, 2차 hidden, close, tray Quit 시나리오를 runner 변경 전 실행합니다.
   - Expected before implementation: multiple process 또는 close exit/hidden show 때문에 실패합니다.
2. Minimal implementation:
   - Action: pre-engine instance coordinator → window lifecycle adapter → tray adapter → device bounds store → package-aware autostart bridge 순으로 작성합니다.
3. Passing verification:
   - Command/check: `fvm flutter test test/app/infrastructure/windows test/contexts/rhythm/infrastructure/windows test/contexts/preferences/infrastructure/windows`, `fvm flutter build windows --release`, Windows integration harness.
   - Expected after implementation: process/window/registration 상태가 launch matrix 기대와 같고 orphan tray/autostart가 남지 않습니다.
4. Regression lock:
   - per-flavor multi-process harness와 exact registry/StartupTask inspection이 한 인스턴스·hidden·identity 계약을 잠급니다.

Notes:

- ordinary user launch와 autostart 모두 persisted active session을 읽지 않으며 Idle로 시작합니다.
- native 코드는 app-local runner에 두고 재사용 가능성을 이유로 local plugin package를 만들지 않습니다.
