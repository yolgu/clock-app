# [P11] Todo 목록과 Calendar 화면 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- 오늘과 선택 날짜의 Todo를 추가·편집·완료·재개·이동·정렬·삭제할 수 있는 접근 가능한 화면을 만듭니다.

Goal linkage:

- Clock의 Today panel과 `/calendar`가 같은 Todo application state와 Local Calendar Date 규칙을 사용해야 합니다.
- Sunday-first 42-cell calendar와 completion group별 reorder를 Windows keyboard와 Android touch에서 제공해야 합니다.

Dependencies:

- depends_on: [[P4](P4.md), [P5](P5.md), [P7](P7.md), [P8](P8.md), [P9](P9.md)]
- parallelizable: true

Required skills:

- [client-ui-best-practices, code-principles]

Boundary mapping:

- Public interface: `TodoViewModel`, `TodayTodoPanel`, `CalendarPage`, `TodoListPanel`, `TodoEditor`를 `public_presentation.dart`로 app shell에 공개합니다.
- Implementation boundary: Notifier가 query/command와 selected date/month를 소유하고 editor field/focus/drag 상태는 local widget state가 소유합니다. 정렬 가능 여부는 Domain 결과를 그대로 반영합니다.
- Out-of-scope adjacent behavior: Todo reminder, UTC conversion, recurring event, server sync, Google Tasks는 추가하지 않습니다.
- Regression scenarios: 완료 Todo 숨김, time 기준 자동 sort, adjacent month date 선택, cross-group drag, delete confirmation/undo snackbar 생성, midnight에 사용자가 고른 날짜 강제 이동을 막습니다.

Files / Resources:

- Create: `lib/contexts/todo/presentation/{todo_view_model.dart,todo_providers.dart,todo_list_panel.dart,todo_row.dart,todo_editor.dart}`, `lib/contexts/todo/presentation/today/today_todo_panel.dart`, `lib/contexts/todo/presentation/calendar/{calendar_page.dart,calendar_grid.dart,calendar_cells.dart,calendar_header.dart}`, 해당 Notifier/widget/golden/accessibility tests.
- Modify: `/clock` Today 영역, `/calendar` branch, route query synchronization.
- Test: add/edit/toggle/reopen/delete, group reorder, move date append, 42 cells, blank adjacent cells, month summary, midnight/timezone selection policy, 25,000 error, 200% text.
- Delete: calendar/Todo placeholder.

Difficulty:

- 🔴 High

Risk:

- drag UI가 visible subset만 넘기거나 완료 상태를 섞으면 Domain의 “같은 날짜·같은 group 전체 순열” 계약과 불일치합니다.

Rollback:

- drag interaction을 비활성화해 accessible move up/down actions만 남겨도 data/order 계약은 유지됩니다. presentation 실패는 application commands나 DB를 되돌리지 않고 해당 widget/Notifier만 이전 상태로 복구합니다.

Completion criteria:

- [ ] incomplete와 completed가 모두 보이고 completed를 reopen할 수 있으며 optional time은 표시만 하고 순서나 notification에 영향을 주지 않습니다.
- [ ] title 입력은 single-line trim, 1–160 grapheme를 검증하고 120부터 counter를 보이며 date/time editor는 Local Calendar Date와 optional `HH:mm`만 전달합니다.
- [ ] reorder는 desktop pointer/keyboard와 mobile drag handle/semantic move up·down을 제공하고 같은 Completion Group 전체에만 적용됩니다.
- [ ] delete는 즉시 영구 command를 보내며 confirm dialog, undo token, Snackbar를 만들지 않습니다.
- [ ] calendar는 Sunday-first 고정 42 cells, 앞뒤 달 날짜는 blank/nonselectable, 날짜별 completed/total summary와 선택/today/has-Todo 상태를 color 외 방식으로 표시합니다.
- [ ] local midnight/timezone 변경 때 선택이 이전 today를 따라가던 경우만 새 today로 이동하고 사용자가 고른 다른 날짜는 유지합니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: `fvm flutter test test/contexts/todo/presentation`에 domain fake와 fake clock으로 CRUD, calendar, reorder, midnight 흐름을 먼저 둡니다.
   - Expected before implementation: view model/widget 부재 또는 잘못된 UI command로 실패합니다.
2. Minimal implementation:
   - Action: TodoViewModel query/selected-date state → Today list → editor → Calendar grid → reorder accessibility action 순으로 화면을 채웁니다.
3. Passing verification:
   - Command/check: presentation/widget tests, representative compact/wide Korean/English goldens, semantics tests.
   - Expected after implementation: 모든 사용자 action이 정확히 하나의 application command를 호출하고 domain-returned ordering과 화면 순서가 같습니다.
4. Regression lock:
   - 42-cell snapshot, midnight policy fake-clock test, group reorder contract test, no-dialog/no-Snackbar assertion이 합의 동작을 잠급니다.

Notes:

- `TodoViewModel`은 1초 clock tick을 구독하지 않습니다. today rollover용 다음 local midnight만 별도 clock signal로 받습니다.
- route query가 바뀌면 selected date를 갱신하되 invalid query 처리는 P7 error route가 소유합니다.
