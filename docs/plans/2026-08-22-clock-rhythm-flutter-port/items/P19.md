# [P19] CI·생성물·아키텍처 품질 게이트 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- 로컬과 GitHub Actions가 같은 FVM SDK, 생성 절차, analyzer, architecture 검사, 테스트와 release build를 반복하도록 자동화합니다.

Goal linkage:

- formatting, analysis, generated consistency, architecture, all tests, Windows/Android release builds가 필수 gate여야 합니다.
- 저장소에는 workflow를 두되 remote 생성/push나 production secret 저장을 하지 않아야 합니다.

Dependencies:

- depends_on: [[P0](P0.md), [P1](P1.md)]
- parallelizable: true

Required skills:

- [code-principles, systematic-debugging]

Boundary mapping:

- Public interface: `tool/verify.ps1`, platform build scripts와 `.github/workflows/*.yml`이 개발자/CI 명령 계약입니다.
- Implementation boundary: scripts가 명령 순서와 exit code를 소유하고 workflows는 runner/tool cache/artifact upload만 조율합니다.
- Out-of-scope adjacent behavior: GitHub remote 생성, branch protection 변경, store upload, secret provisioning, arbitrary coverage threshold는 하지 않습니다.
- Regression scenarios: 로컬은 FVM인데 CI는 floating Flutter, stale Drift/l10n 생성물 통과, Windows native tests 누락, build failure 뒤 artifact upload를 막습니다.

Files / Resources:

- Create: `.github/workflows/windows.yml`, `.github/workflows/android.yml`, `tool/{verify.ps1,generate.ps1,check_generated.ps1,build_windows.ps1,build_android.ps1}`, `docs/verification/ci-gates.md`.
- Modify: `pubspec.yaml` dev dependencies, `.gitignore`, 각 P-item이 추가한 테스트/플랫폼 harness를 공통 script에 등록합니다.
- Test: script exit-code harness, intentionally stale generated file, forbidden import fixture, failing unit/native test, missing signing credential behavior.
- Delete: FVM을 우회하거나 성공 exit를 강제하는 중복 build commands.

Difficulty:

- 🟡 Medium

Risk:

- workflow가 완성 전 기능 파일을 참조하도록 한 번에 작성되면 초기 단계가 계속 red 상태가 되어 실제 회귀와 계획된 미완성을 구분하기 어렵습니다.

Rollback:

- P19 최초 완료는 P0/P1 smoke gate까지만 green으로 만들고, 이후 P-item이 자기 tests/build step을 같은 scripts에 추가합니다. 새 gate가 오탐이면 해당 step만 진단 상태로 되돌리되 기존 gate를 제거하지 않습니다.

Completion criteria:

- [ ] 모든 명령은 `.fvmrc` Flutter 3.44.7과 `pubspec.lock`을 사용하고 floating Git/plugin dependency가 없습니다.
- [ ] 공통 gate가 gen_l10n/Drift generation, generated diff, format, analyze, architecture check, Dart/Flutter tests를 순서대로 실행하고 첫 실패 exit code를 보존합니다.
- [ ] Windows job은 Windows tests/native harness와 release Windows build를, Android job은 Dart/Kotlin tests와 release APK/AAB build를 수행합니다.
- [ ] third-party Actions는 mutable tag만 쓰지 않고 검토한 commit SHA에 pin하며 cache key가 Flutter version과 lockfile을 포함합니다.
- [ ] production signing material이 없으면 production-signing step이 명확히 fail/skip 조건을 보고하고 debug key나 빈 password로 production artifact를 위장하지 않습니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: generated file을 의도적으로 stale하게 만들고 forbidden fixture를 켠 상태에서 `powershell -ExecutionPolicy Bypass -File tool/verify.ps1`을 실행합니다.
   - Expected before implementation: script 부재 또는 잘못된 성공 exit 때문에 probe가 실패합니다.
2. Minimal implementation:
   - Action: 로컬 scripts를 먼저 작성해 각 명령과 artifact 경로를 단일화하고, Windows/Android workflow가 그 scripts만 호출하게 합니다.
3. Passing verification:
   - Command/check: clean tree에서 `tool/verify.ps1`, `tool/build_windows.ps1 -Flavor Beta`, `tool/build_android.ps1 -Flavor Beta -Artifact Apk`; workflow YAML lint.
   - Expected after implementation: clean inputs은 green, 각 injected failure는 해당 단계 이름과 nonzero exit로 red입니다.
4. Regression lock:
   - script self-test와 generated/architecture negative fixtures가 gate가 형식만 남고 무력화되는 것을 막습니다.

Notes:

- 전역 coverage percentage를 성공 기준으로 쓰지 않습니다. P22의 behavior traceability와 platform matrix가 coverage 의미를 소유합니다.
- workflow는 저장소에만 추가하며 사용자가 remote를 만들고 push하기 전에는 외부 상태를 바꾸지 않습니다.
