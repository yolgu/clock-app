# [P12] Clock과 Rhythm Session 화면 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- 현재 wall clock, 다음 Rhythm Event, session 상태와 Start/Pause/Resume/Stop for Today 조작을 과도한 rebuild 없이 명확하게 보여줍니다.

Goal linkage:

- source의 analog/digital clock과 rhythm controls를 behavioral parity로 옮겨야 합니다.
- 화면이 보일 때만 1Hz로 시계를 갱신하고 assistive technology를 매초 방해하지 않아야 합니다.

Boundary mapping:

- Public interface: `RhythmViewModel`, `ClockPage`, `AnalogClock`, `DigitalClock`, `RhythmControls`, `RhythmStatusPanel`을 `public_presentation.dart`로 공개합니다.
- Implementation boundary: Notifier는 Rhythm application snapshots/commands와 delivery capability result를 소유하고, 1Hz visual tick은 Clock subtree의 local listenable이 소유합니다.
- Out-of-scope adjacent behavior: Windows/Android delivery adapter 자체, 알림음 재생, OS 권한 요청은 fake port로만 다룹니다.
- Regression scenarios: 전체 앱 매초 rebuild, offstage timer 지속, resume 시 countdown shift, denied permission 뒤 running 표시, analog clock semantic 중복을 막습니다.

Difficulty:

- 🔴 High

Risk:

- timer를 Riverpod 전역 상태에 두면 모든 소비자가 초마다 rebuild되고 offstage indexed branch에서도 계속 깨워 배터리와 접근성 품질이 나빠집니다.

Rollback:

- domain/application session은 유지하고 analog animation을 정적 표시로 낮출 수 있습니다. ticker가 불안정하면 visible route의 `Timer.periodic`과 `RepaintBoundary`만 이전 검증 방식으로 교체합니다.

Completion criteria:

- [ ] visible Clock branch만 wall clock을 1초마다 sample하고 clock subtree만 repaint하며 offstage에서는 timer를 취소합니다.
- [ ] 다시 visible이 되거나 app resume 시 즉시 실제 시각과 Rhythm snapshot을 reconcile한 뒤 1Hz tick을 재개합니다.
- [ ] analog face는 semantics tree에서 decorative로 제외하고 digital time은 읽을 수 있지만 live region이 아니며 매초 announcement하지 않습니다.
- [ ] Idle/Running/Paused/Stopped for Today와 창 밖 armed 상태의 다음 발생 시각을 color 외 text/icon으로 구분합니다.
- [ ] Start가 delivery capability failure를 반환하면 session을 Idle로 유지하고 localized 설명/action을 표시하며 성공을 가장하지 않습니다.
- [ ] Pause/Resume/Stop controls는 현재 상태에서 가능한 command만 활성화하고 의미 있는 상태 변화만 한 번 announce합니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: fake clock과 fake delivery capability로 `fvm flutter test test/contexts/rhythm/presentation test/app/presentation/clock_page_test.dart`를 먼저 작성합니다.
   - Expected before implementation: ticker/Notifier/widget 부재 또는 broad rebuild count 때문에 실패합니다.
2. Minimal implementation:
   - Action: application snapshot Notifier → controls → digital clock → CustomPainter analog clock → route visibility-aware ticker 순으로 작성합니다.
3. Passing verification:
   - Command/check: widget tests, semantics tests, rebuild counter test, representative goldens, analyzer.
   - Expected after implementation: fake time advance가 clock subtree만 갱신하고 상태 command/result와 UI가 정확히 일치합니다.
4. Regression lock:
   - ticker lifecycle/rebuild counter와 semantics snapshot이 매초 전역 갱신·offstage tick·live announcement 회귀를 막습니다.
