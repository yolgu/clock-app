# [P7] 복원 가능한 앱 셸과 안정 route 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- 네 개의 제품 목적지를 고정 URL과 보존 가능한 branch state로 제공하고 Windows·Android에 맞는 navigation chrome을 선택합니다.

Goal linkage:

- `/clock`, `/calendar?date=YYYY-MM-DD`, `/data`, `/theme` 계약과 Android back 의미를 보존해야 합니다.
- Windows top segmented navigation과 Android bottom navigation이 같은 route state를 사용해야 합니다.

Dependencies:

- depends_on: [[P1](P1.md)]
- parallelizable: true

Required skills:

- [client-ui-best-practices, code-principles]

Boundary mapping:

- Public interface: `AppRoute`, `ClockRhythmRouter`, `AppShell`, `PlatformPresentationProfile`이 application shell 계약입니다.
- Implementation boundary: `go_router` configuration과 restoration scope는 `app/navigation`, adaptive chrome은 `app/presentation`, 플랫폼 선택은 composition에서 주입하는 profile에 둡니다.
- Out-of-scope adjacent behavior: 각 branch 본문 기능, 권한/알림, window native API는 placeholder contract까지만 둡니다.
- Regression scenarios: navigation 때 branch scroll/form state 소실, malformed date를 오늘로 바꿈, unknown route를 clock으로 삼킴, Android secondary route에서 바로 앱 종료를 막습니다.

Files / Resources:

- Create: `lib/app/navigation/{app_routes.dart,app_router.dart,route_error.dart}`, `lib/app/presentation/{app_shell.dart,windows_top_navigation.dart,android_bottom_navigation.dart,route_error_page.dart}`, `lib/app/platform_presentation_profile.dart`, `test/app/navigation/**`, `test/app/presentation/app_shell_test.dart`.
- Modify: `lib/main.dart`, `lib/app/clock_rhythm_app.dart`, `lib/app/composition/app_composition.dart`.
- Test: route parse/restore, branch state retention, query date validation, Android back stack, Windows/Android chrome widget tests.
- Delete: 임시 bootstrap home widget.

Difficulty:

- 🟡 Medium

Risk:

- route와 탭 선택 상태를 별도로 소유하면 deep link, restoration, back 처리에서 서로 다른 목적지를 가리킬 수 있습니다.

Rollback:

- 네 route 상수와 branch key를 유지한 채 shell chrome만 단순화할 수 있습니다. router migration 실패 시 placeholder branch를 사용하되 URL 계약을 되돌리지 않습니다.

Completion criteria:

- [x] `StatefulShellRoute.indexedStack`가 네 branch와 고유 navigator/restoration key를 소유하고 branch 상태가 route 전환·resize에서 유지됩니다.
- [x] `/calendar?date=`는 유효한 Local Calendar Date만 받고 malformed query와 unknown route는 localized error model을 표시합니다.
- [x] Android back은 modal/detail을 먼저 닫고 secondary main destination이면 `/clock`으로 이동하며 `/clock`에서만 system exit에 위임합니다.
- [x] Windows는 top segmented control과 `Ctrl+1`–`Ctrl+4`, Android는 bottom navigation을 사용하고 두 UI는 router를 유일한 선택 상태로 봅니다.
- [x] restoration 후 선택 branch, calendar date, branch scroll state가 재구성됩니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: `fvm flutter test test/app/navigation test/app/presentation/app_shell_test.dart`에 URL/back/restoration 표를 먼저 추가합니다.
   - Expected before implementation: route parser 또는 shell 부재로 실패합니다.
2. Minimal implementation:
   - Action: route value와 strict parser를 만든 뒤 indexed shell, platform chrome, back policy, restoration scope를 순서대로 작성합니다.
3. Passing verification:
   - Command/check: 위 widget tests와 `fvm flutter analyze`.
   - Expected after implementation: Windows/Android profile 각각에서 같은 route가 정확한 chrome과 branch를 선택하고 invalid location은 error page로 갑니다.
4. Regression lock:
   - parameterized router test와 restoration round-trip이 route string, branch index, back 정책을 잠급니다.

Notes:

- `Platform.isWindows` 같은 검사는 widget/ViewModel에 두지 않습니다. composition root가 runtime capability로 `PlatformPresentationProfile`을 선택합니다.
- 네 route는 손으로 선언하며 `go_router_builder`를 추가하지 않습니다.
