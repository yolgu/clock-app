# [P6] Portable Backup v1 codec과 원자적 교체 흐름 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- Neutralino와 Flutter beta/production 사이에서 왕복 가능한 plain JSON v1 계약을 엄격히 읽고 쓰며, 확인된 전체 교체를 안전한 순서로 조율합니다.

Goal linkage:

- 기존 schema version 1을 version bump 없이 import/export하고 custom media와 transient state를 제외해야 합니다.
- 잘못된 파일 한 항목도 전체 import를 거부하고 durable data는 부분 변경되지 않아야 합니다.

Dependencies:

- depends_on: [[P2](P2.md), [P3](P3.md), [P4](P4.md), [P5](P5.md)]
- parallelizable: false

Required skills:

- [code-principles, systematic-debugging]

Boundary mapping:

- Public interface: `PrepareBackupImport`, `ConfirmBackupImport`, `ExportPortableBackup`, `PreparedBackupImport`, `BackupPreview`, `BackupFilePort`, `BackupReplacementPort`, `RhythmSafetyPort`만 feature public surface로 노출합니다.
- Implementation boundary: application이 Preferences/Todo 공개 snapshot을 조합하고, handwritten codec이 untrusted JSON을 검증하며, app-owned Drift adapter가 transaction을 실행합니다.
- Out-of-scope adjacent behavior: file picker UI, OS share sheet, recovery screen, Windows autostart 구체 API는 이후 항목이 맡습니다.
- Regression scenarios: 32MiB/25,000 제한 검사 전에 세션 중단, invalid Todo 하나만 건너뜀, unknown version 추측, custom path 유출, DB commit 전에 autostart side effect 실행을 막습니다.

Difficulty:

- 🔴 High

Risk:

- legacy restore의 관대한 default와 present-invalid 거부를 구분하지 않으면 손상 파일을 정상으로 받아들이거나 유효한 이전 파일을 거절할 수 있습니다.

Rollback:

- parser/serializer는 version별 순수 codec으로 격리합니다. v1 회귀가 생기면 UI나 DB schema를 되돌리지 않고 codec과 fixture만 이전 상태로 복구할 수 있습니다. 실제 import 전 preflight와 확인을 분리해 실패 실험이 사용자 DB에 닿지 않게 합니다.

Completion criteria:

- [ ] envelope는 `appName: "Clock Rhythm"`, integer `schemaVersion: 1`, 유효한 `exportedAt`, `preferences`, `todos`를 요구하고 unknown additive field는 수용·다음 export에서 제거하며 unknown version은 거부합니다.
- [ ] 파일은 32MiB 이하, Todo는 최대 25,000개이며 이 두 제한과 전체 parse/validation이 세션·소리·DB 변경 전에 끝납니다.
- [ ] missing optional legacy Preferences는 Korean/`current`/default sound/initialSetup false로 보완하고, present invalid 값은 거부하며 valid custom sound는 media 비휴대성 때문에 default로 sanitize합니다.
- [ ] 모든 Todo의 nonempty ID(최대 128자)·title·Gregorian date·optional HH:mm·Boolean·parseable timestamps(`updatedAt >= createdAt`)·음이 아닌 integer `displayOrder`를 검증하고 invalid index를 localized error key로 반환하되 title을 preview/log에 넣지 않습니다.
- [ ] 확인 시 먼저 active schedule/audio를 취소해 Idle로 만들고, 그 뒤 한 DB transaction으로 Preferences/Todos를 교체합니다. DB 실패여도 세션은 Idle, durable data는 이전 값입니다.
- [ ] DB commit 후 Windows autostart를 desired value와 reconcile하며 실패하면 imported preference를 유지하고 repair state를 반환합니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: `fvm flutter test test/features/data_transfer`에 각 fixture와 fault-injected replacement ordering test를 먼저 실행합니다.
   - Expected before implementation: codec 부재 또는 검증·side-effect 순서 불일치로 실패합니다.
2. Minimal implementation:
   - Action: byte gate → JSON decode → envelope/type/value validation → domain restore → redacted preview → explicit confirm → rhythm safety → DB transaction → autostart reconciliation 순서를 타입으로 분리합니다.
3. Passing verification:
   - Command/check: `fvm flutter test test/features/data_transfer --reporter expanded`와 P5 transaction integration tests.
   - Expected after implementation: valid legacy fixtures는 round trip하고 모든 invalid fixture는 durable/session precondition에 맞는 결과를 냅니다.
4. Regression lock:
   - 실제 Neutralino export fixture를 byte-for-byte parser 입력으로 보관하고 export→import→export의 의미 동등성 테스트가 v1 계약을 잠급니다.

Notes:

- `displayOrder`가 없는 legacy Todo는 `createdAt`으로 파생하고, 값이 있으면 유지합니다. 동률은 `createdAt`, `id`로 정렬합니다.
- retired `googleTaskId`를 포함한 unknown additive field는 읽되 제품 model로 복원하지 않고 다음 export에서 제거합니다.
- preview에는 total/completed counts, date range, rhythm, language, theme, autostart impact, export time, custom sanitization만 표시합니다.
- Portable Backup은 Android System Backup과 다른 개념이며 plain text·password 없음 경고를 UI 계약에 포함합니다.
