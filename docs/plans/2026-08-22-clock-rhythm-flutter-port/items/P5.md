# [P5] Drift 영속성·마이그레이션·복구 경계 작성

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- Preferences와 Todos를 하나의 SQLite transaction 경계에 저장하되 각 컨텍스트의 repository 계약과 데이터 소유권을 유지합니다.

Goal linkage:

- durable data가 OS private app storage에 남고 schema migration이나 corruption 실패 때 조용히 빈 DB로 초기화되지 않아야 합니다.
- Portable Backup 전체 교체가 원자적으로 실행될 기반을 제공해야 합니다.

Dependencies:

- depends_on: [[P2](P2.md), [P3](P3.md), [P4](P4.md)]
- parallelizable: false

Required skills:

- [code-principles, systematic-debugging]

Boundary mapping:

- Public interface: 컨텍스트는 `SettingsRepository`, `TodoRepository`만 봅니다. app-owned database와 DAO, schema/migration은 infrastructure 내부입니다.
- Implementation boundary: `ClockRhythmDatabase`가 connection과 transaction을 소유하고 context-specific mapper/repository가 row↔domain 변환을 소유합니다. 교차 컨텍스트 replacement adapter는 app infrastructure에 둡니다.
- Out-of-scope adjacent behavior: Portable Backup JSON 해석, Android transient session, window bounds, draft, permission state는 DB table에 넣지 않습니다.
- Regression scenarios: 부분 import commit, migration 실패 후 빈 DB 생성, invalid row coercion, Android backup에 transient state 포함, repository에서 business sort 재정의를 막습니다.

- Delete: 없음.

Difficulty:

- 🔴 High

Risk:

- Preferences singleton과 Todo bulk replacement를 서로 다른 connection/repository save로 처리하면 import 도중 앱 종료 시 반쪽 상태가 남습니다.

Rollback:

- migration 전에 DB 파일을 보존하고 schema version별 fixture를 유지합니다. migration/open 실패 시 파일을 rename·delete하지 않고 recovery state로 진입합니다. 개발 중 schema를 다시 설계할 때도 committed migration을 수정하지 않고 다음 version migration을 추가합니다.

Completion criteria:

- [ ] Preferences singleton row와 Todos rows가 한 `ClockRhythmDatabase` connection에 있고 repository는 domain snapshot을 엄격히 복원합니다.
- [ ] `replaceAll(preferences, todos)`가 한 Drift transaction 안에서만 두 데이터 집합을 교체하며 중간 fault fixture가 기존 DB를 그대로 남깁니다.
- [ ] schema 생성과 모든 migration이 transaction으로 실행되고, 실패·corruption 시 원본 파일 경로를 보존한 `DatabaseRecoveryRequired` startup state가 반환됩니다.
- [ ] DB는 OS private app data 경로에 평문으로 저장되며 release log에 Todo title이나 전체 custom path를 남기지 않습니다.
- [ ] session/AlarmManager ID/permission/window/draft/device path는 durable product table에서 제외됩니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: `fvm flutter test test/app/infrastructure/persistence test/contexts/preferences/infrastructure/persistence test/contexts/todo/infrastructure/persistence`에서 transaction 중 fault와 corrupt fixture를 먼저 실행합니다.
   - Expected before implementation: repository 부재, 부분 write, 또는 silent reset 시나리오 때문에 실패합니다.
2. Minimal implementation:
   - Action: table과 mapper를 작성하고 real SQLite connection을 주입 가능한 factory로 감싼 뒤 repository와 app-owned replacement transaction을 붙입니다. 외부 row는 domain restore를 반드시 통과시킵니다.
3. Passing verification:
   - Command/check: `fvm dart run build_runner build --delete-conflicting-outputs`, 위 integration tests, `fvm flutter analyze`.
   - Expected after implementation: 생성 파일이 최신이며 cold create/open/rollback/recovery가 모두 통과합니다.
4. Regression lock:
   - versioned DB fixtures와 failure injection이 migration·transaction 원자성, row validation, no-silent-reset을 잠급니다.

Notes:

- 앱 수준 암호화나 password DB는 추가하지 않습니다. 프라이버시는 OS private storage, 최소 로그, backup 제한으로 지킵니다.
- `shared_preferences`는 window/draft 같은 교체 가능한 device UI state에만 쓰고 DB truth를 복제하지 않습니다.
