# [P0] 독립 저장소와 고정 도구체인 부트스트랩

Parent plan:

- [전체 계획](../plan.md)

Status:

- Done

Purpose:

- 비어 있는 대상 디렉터리를 Windows와 Android에서 재현 가능한 Flutter 저장소로 만들고, 이후 작업이 동일한 SDK와 잠금 파일을 사용하게 합니다.

Goal linkage:

- Windows 10/11 x64와 Android API 24+를 동일한 Flutter 소스에서 빌드할 수 있어야 합니다.
- Flutter 3.44.7, FVM, 잠긴 pub.dev 의존성을 로컬과 CI의 단일 도구체인 계약으로 사용해야 합니다.
- 원본 Neutralino 저장소는 읽기 전용 참조로 남기고 대상은 독립 Git 저장소여야 합니다.

Dependencies:

- depends_on: []
- parallelizable: false

Required skills:

- [code-principles, directory-architecture]

Boundary mapping:

- Public interface: `pubspec.yaml`, `.fvmrc`, `analysis_options.yaml`, Flutter가 생성한 Windows/Android runner, 공통 검증 스크립트가 저장소의 빌드 계약입니다.
- Implementation boundary: 이 항목은 앱 동작을 넣지 않고 SDK, 프로젝트 메타데이터, 플랫폼 셸, 의존성 잠금만 소유합니다.
- Out-of-scope adjacent behavior: 제품 화면, Drift 스키마, 알람·트레이 동작, 서명 자격 증명, Git 원격 생성과 push는 다루지 않습니다.
- Regression scenarios: 문서가 덮어써짐, 서로 다른 Flutter 버전 사용, Android 최소 SDK 또는 application ID 변동, Windows runner 누락, 프로덕션 비밀정보 커밋을 막습니다.

Files / Resources:

- Create: `.git/`, `.fvmrc`, `.gitignore`, `pubspec.yaml`, `pubspec.lock`, `analysis_options.yaml`, `l10n.yaml`, `lib/main.dart`, `test/smoke/app_bootstrap_test.dart`, `android/`, `windows/`, `tool/verify.ps1`, `tool/preflight.ps1`.
- Modify: Flutter 생성 후 `android/app/build.gradle.kts`, `android/app/src/main/AndroidManifest.xml`, `windows/CMakeLists.txt`, `windows/runner/Runner.rc`; 제품 표시명은 `Clock Rhythm`, Dart 패키지는 `clock_rhythm`, Windows 실행 파일은 `clock_rhythm.exe`, Android production namespace/application ID는 `dev.wndls.clockrhythm`으로 고정합니다.
- Test: `test/smoke/app_bootstrap_test.dart`, Windows debug 실행, Android API 24·36 emulator debug 실행.
- Delete: Flutter 기본 counter 예제와 해당 예제 테스트만 제거합니다. `CONTEXT.md`, `docs/adr/**`는 보존합니다.

Difficulty:

- 🟡 Medium

Risk:

- 현재 워크스테이션에서 `flutter`, `fvm`, Visual Studio C++ workload, Android SDK/라이선스가 확인되지 않았으므로 시스템 준비 없이 생성 명령부터 실행하면 불완전한 runner나 재현 불가능한 잠금 파일이 생길 수 있습니다.

Rollback:

- 생성 전 대상 파일 목록과 해시를 기록합니다. 실패 시 Flutter가 새로 만든 경로만 목록에 따라 제거하고 기존 `CONTEXT.md`와 `docs/adr/**`를 그대로 둡니다. Git 초기화가 끝난 뒤에는 해당 P-item의 변경만 역패치하며 원본 저장소에는 어떤 쓰기도 하지 않습니다.

Completion criteria:

- [x] 사용자가 Flutter/FVM, Visual Studio Desktop development with C++, Android Studio/SDK API 36을 설치하고 Android 라이선스를 직접 검토·수락했으며 `fvm flutter doctor -v`에 Windows/Android 차단 오류가 없습니다.
- [x] `.fvmrc`가 Flutter `3.44.7`을 가리키고 `pubspec.lock`이 커밋 대상이며 모든 로컬·CI 명령이 `fvm`을 통합니다.
- [x] `clock_rhythm`이 Windows와 Android에서 기본 셸을 열고 기존 문서 23개가 바뀌거나 사라지지 않습니다.
- [x] 대상은 독립 Git 저장소이고 remote가 없으며, 원본 `C:\Users\wndls\projects\clock-app`의 상태와 사용자 파일이 변경되지 않습니다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: `powershell -ExecutionPolicy Bypass -File tool/preflight.ps1`에 들어갈 각 검사와 동일하게 `fvm --version`, `fvm flutter --version`, `fvm flutter doctor -v`를 실행합니다.
   - Expected before implementation: 현재 상태에서는 FVM/Flutter 또는 Windows·Android 도구체인 누락이 명시적인 실패로 보고됩니다. 자동 설치나 라이선스 자동 수락은 일어나지 않습니다.
2. Minimal implementation:
   - Action: `git init`으로 대상만 초기화하고, FVM 3.44.7을 선택한 뒤 `fvm flutter create --platforms=windows,android --org dev.wndls --project-name clock_rhythm .`로 셸을 생성합니다. 합의된 핵심 패키지와 플랫폼 플러그인을 안정 pub.dev 버전으로 고정하고 lockfile을 생성합니다.
3. Passing verification:
   - Command/check: `powershell -ExecutionPolicy Bypass -File tool/verify.ps1`, `fvm flutter build windows --debug`, `fvm flutter build apk --debug`.
   - Expected after implementation: 포맷·분석·smoke test와 두 debug build가 성공하고 Flutter 버전 및 package resolution이 lockfile과 일치합니다.
4. Regression lock:
   - `tool/preflight.ps1`은 SDK, doctor, API 36, Windows toolchain을 진단하고, smoke test는 앱 진입점이 예제 counter로 되돌아가지 않게 잠급니다.

Notes:

- 초기 `pubspec.yaml`에는 `flutter_riverpod` 3.4.x, `go_router` 17.5.x, `drift` 2.34.x, `drift_flutter` 0.3.x와 합의된 플랫폼 패키지를 직접 의존성으로 선언합니다. 정확한 patch 버전은 P0 실행 시 안정 pub.dev 릴리스를 선택한 뒤 lockfile이 SSOT가 됩니다.
- Drift와 Flutter `gen_l10n`만 생성기를 사용합니다. Riverpod Generator, Freezed, `go_router_builder`, GetIt은 추가하지 않습니다.
- 시스템 도구 설치와 production signing material 제공은 저장소 변경과 분리된 사용자 개입입니다.
