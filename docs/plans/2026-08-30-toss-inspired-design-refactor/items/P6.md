Files / Resources:

Difficulty:

- 🔴 High

Risk:

- Android emulator가 현재 연결되지 않아 실제 Android 렌더링 증거를 얻지 못할 수 있다.

Rollback:

- 실패가 발생한 마지막 P-item의 source/test/golden 변경만 되돌리고 통과한 증거를 보존한 채 재실행한다.

Completion criteria:

- [ ] format, architecture check, analyze, complete Flutter test가 exit code 0이다.
- [ ] Windows beta build가 성공하고 실제 창에서 핵심 화면과 상호작용 상태를 검사한다.
- [ ] Android beta APK build가 성공하며 emulator 부재 시 렌더링 한계를 명시한다.
- [ ] `VISUAL_QA.md`에 열린 시각 finding이 없고 최종 evidence path가 기록된다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: focused test 이후 `tool/verify.ps1 -Platform Core`와 platform build를 실행한다.
   - Expected before implementation: 변경으로 인한 남은 format/analyze/test/build 오류가 있으면 해당 owner로 분류된다.
2. Minimal implementation:
   - Action: current change가 만든 오류와 시각 discrepancy만 owning P-item 범위에서 수정한다.
3. Passing verification:
   - Command/check: `powershell -ExecutionPolicy Bypass -File tool/verify.ps1 -Platform Core`, `powershell -ExecutionPolicy Bypass -File tool/build_windows.ps1 -Flavor Beta`, `powershell -ExecutionPolicy Bypass -File tool/build_android.ps1 -Flavor Beta -Artifact Apk`.
   - Expected after implementation: 세 명령이 exit code 0이며 Windows 실렌더링 QA가 pass이다.
4. Regression lock:
   - 최종 command log, screenshots, `VISUAL_QA.md`, execution ledger가 build와 source 상태에 귀속된다.

Notes:

- production credential, signing, package 게시, 계정 데이터는 다루지 않는다.
