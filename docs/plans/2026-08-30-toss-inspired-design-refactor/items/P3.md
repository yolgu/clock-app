# [P3] Windows 상단 내비게이션을 인라인 탭으로 변경

Parent plan:

- [전체 계획](../plan.md)

Status:

- Pending

Purpose:

- 큰 segmented pill을 52px 인라인 탭 strip으로 바꾸면서 기존 목적지, 단축키, 포커스, 선택 semantics를 보존한다.

Goal linkage:

- G1 토스형 내비게이션 밀도, G4 Windows 키보드와 접근성 보존.

Dependencies:

- depends_on: [[P2](P2.md)]
- parallelizable: true

Required skills:

- [code-principles, client-ui-best-practices, superloopy-frontend]

Boundary mapping:

- Public interface: `WindowsTopNavigation` constructor와 `ValueChanged<int>` callback.
- Implementation boundary: `lib/app/presentation/windows_top_navigation.dart` 내부 destination tab.
- Out-of-scope adjacent behavior: `StatefulNavigationShell`, route 목록, Ctrl+1~4 단축키, Android navigation.
- Regression scenarios: left/right/up/down 이동, 첫/끝 clamp, 선택 destination 재호출, Tab focus, 200% text.

Files / Resources:

- Create: 공용 의미가 없는 경우 별도 파일 없이 private destination widget을 같은 파일에 둔다.
- Modify: `lib/app/presentation/windows_top_navigation.dart`, 필요한 theme token consumer.
- Test: `test/app/presentation/app_shell_test.dart`, `test/accessibility/focus_order_test.dart`, 새 `test/app/presentation/windows_top_navigation_test.dart`.
- Delete: `WindowsTopNavigation`의 `SegmentedButton` 사용.

Difficulty:

- 🔴 High

Risk:

- custom tab이 선택 상태를 시각적으로만 표시하거나 키보드 focus order를 바꾸면 Windows 접근성 계약이 깨진다.

Rollback:

- private tab widget을 제거하고 기존 `SegmentedButton<MainDestination>` 트리를 복원한다.

Completion criteria:

- [ ] 52px strip에서 네 destination이 의미 있는 button/selected semantics와 48px hit target을 가진다.
- [ ] selected text·blue indicator, hover·pressed surface, visible focus가 semantic tokens에서 나온다.
- [ ] 기존 arrow 이동과 destination callback 동작이 widget test로 고정된다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: 새 navigation 테스트에 높이, `SegmentedButton` 부재, selected semantics, arrow 이동을 작성해 실행한다.
   - Expected before implementation: 기존 segmented control 구조 때문에 실패한다.
2. Minimal implementation:
   - Action: shell callback을 유지한 private tab button과 indicator를 작성하고 기존 shortcut wrapper에 배치한다.
3. Passing verification:
   - Command/check: navigation, app shell, focus-order 테스트 실행.
   - Expected after implementation: mouse/keyboard 경로와 semantics가 모두 통과한다.
4. Regression lock:
   - 네 destination 순서, clamp, 선택 상태, focus traversal을 테스트가 고정한다.

Notes:

- OS caption 영역이나 window chrome은 변경하지 않는다.
