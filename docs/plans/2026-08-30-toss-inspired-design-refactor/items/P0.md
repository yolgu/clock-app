- 새 계약·증거 문서만 제거하고 기존 미커밋 코드와 골든은 그대로 둔다.

Completion criteria:

- [ ] 기준선이 현재 작업 트리의 미커밋 변경을 포함한다는 사실이 기록된다.
- [ ] 소스 토큰의 적용·적응·제외 범위가 컴포넌트 명세에 명시된다.
- [ ] Windows와 Android의 변경 주장 및 증거 종류가 UX 계약에 연결된다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: `git status --short`, 관련 4개 Flutter 테스트 파일 실행.
   - Expected before implementation: 미커밋 디자인 파일이 식별되고 기준선 23개 테스트가 통과한다.
2. Minimal implementation:
   - Action: 연구 결과를 UX 계약과 Flutter 컴포넌트 명세로 옮기고 타임스탬프 증거 루트를 만든다.
3. Passing verification:
   - Command/check: `tool/check_docs.ps1`, 문서 내 토큰·타깃·증거 경로 검색.
   - Expected after implementation: 링크가 유효하고 모든 변경 주장이 소유자와 검증 경로를 가진다.
4. Regression lock:
   - 현재 기준선과 사용자 미커밋 파일 목록이 실행 ledger에 남아 이후 단계가 이를 보존한다.
