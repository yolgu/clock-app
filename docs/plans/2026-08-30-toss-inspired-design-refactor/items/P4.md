# [P4] 기능 화면의 토큰 소비 정리

Parent plan:

- [전체 계획](../plan.md)

Status:

- Pending

Purpose:

- Clock, Rhythm, Todo, Calendar, Preferences, Theme, Data, recovery 화면이 shared token과 panel 계약을 일관되게 소비하게 한다.

Goal linkage:

- G1 전체 앱의 일관된 시각 언어, G3 literal drift 제거, G4 적응형 정보 구조 보존.

Dependencies:

- depends_on: [[P2](P2.md)]
- parallelizable: true

Required skills:

- [code-principles, client-ui-best-practices, superloopy-frontend]

Boundary mapping:

- Public interface: 기존 page/panel/widget constructor와 사용자 상호작용.
- Implementation boundary: presentation 파일의 geometry, surface, spacing, typography 소비.
- Out-of-scope adjacent behavior: ViewModel, notifier, use case, repository, domain model.
- Regression scenarios: rhythm command, Todo edit/reorder, Calendar 선택, settings draft, sound preview, import/export dialog.

Files / Resources:

- Create: 새 shared primitive는 두 개 이상의 안정된 의미 계약이 확인될 때만 추가한다.
- Modify: `lib/app/presentation/clock_page.dart`, recovery/error pages, `lib/contexts/rhythm/presentation/`, `lib/contexts/todo/presentation/`, `lib/contexts/preferences/presentation/`, `lib/features/data_transfer/presentation/`의 현재 미커밋 디자인 파일 중 token 소비가 필요한 파일.
- Test: 각 변경 파일과 가장 가까운 기존 widget test, Calendar/Preferences/Data test support.
- Delete: shared token으로 대체되는 presentation literal과 중복 card wrapper.

Difficulty:

- 🔴 High

Risk:

- 대규모 시각 치환 중 form draft, scroll restoration, semantics key, test finder를 실수로 바꿀 수 있다.

Rollback:

- 기능별 diff를 분리해 실패한 feature 묶음만 이전 token consumer로 되돌린다. 상태·domain 파일은 변경 대상에서 제외한다.

Completion criteria:

- [ ] 대상 presentation 파일의 4/8 scale 밖 geometry가 이유 없는 literal로 남지 않는다.
- [ ] 모든 panel이 card/surface 역할과 spacing owner를 하나만 가진다.
- [ ] 기능별 widget test가 기존 사용자 행동과 key/semantics를 보존한다.

TDD / Validation steps:

1. Failing probe or failing test:
   - Command/check: token usage 검색과 기존 feature widget test를 실행하고 새 theme 적용 후 깨지는 golden/widget 계약을 기록한다.
   - Expected before implementation: 6px/2px처럼 컴포넌트 고유 값은 정당한 예외로 남고, 중복 12/16/24 literal 및 card geometry는 drift 후보로 식별된다.
2. Minimal implementation:
   - Action: feature 묶음별로 shared token import와 component theme 소비만 수정하고 state/data 코드는 유지한다.
3. Passing verification:
   - Command/check: `fvm flutter test test/contexts/rhythm/presentation test/contexts/todo/presentation test/contexts/preferences/presentation test/features/data_transfer/presentation`.
   - Expected after implementation: 기능 동작, form draft, reorder, Calendar selection, recovery state 테스트가 통과한다.
4. Regression lock:
   - 사용자 행위 테스트와 golden이 시각 변경과 기능 불변을 함께 고정한다.

Notes:

- 관련 없는 리팩터링과 새 architecture layer는 만들지 않는다.
