## Extraction and counting rule

The inventory starts from `git ls-tree -r --name-only <commit>` and retains tracked paths ending in `.test.ts` or `.test.tsx`. Each file is parsed from the pinned Git object with the TypeScript 6.0.3 compiler API. A behavior row is created only for a `CallExpression` whose callee is the direct identifier `it` or `test`. Literal `describe` ancestors are retained in outer-to-inner order and joined to the exact literal case title with ` › `.

A historical text search reported 183 matches because `\b(?:it|test)\s*\(` also matched `RegExp.prototype.test()` in `src/shared/i18n/catalog.test.ts` line 35 (`/rhythm/i.test(text)`). That expression is an assertion helper call, not a Vitest case, so it is documented here but is not represented as a behavior row.

## Evidence status

Every row names the P-item responsible for implementing or dispositioning the behavior. `Verified` names an existing passing evidence path and completion date. `Dispositioned` records an accepted ADR-backed replacement, retirement, or unsupported-platform boundary without presenting it as a passing compatibility test. `Pending` is reserved for a behavior that has neither form of evidence. P22 must still bind the automated set to the final artifact manifest before release qualification. macOS and Linux autostart are explicitly dispositioned under the Windows-and-Android target rather than recorded as manual passes.
